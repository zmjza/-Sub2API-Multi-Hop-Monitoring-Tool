# macOS 真机验收证据

验收日期：2026-07-14<br>
平台：macOS 26.5、Apple Silicon<br>
应用：`release/mac-arm64/Sub2API 多站监控.app`<br>
数据隔离：使用 `/tmp/sub2api-real-device.V7T1ho`，不接触日常应用数据。<br>
发布属性：未签名、未公证的内部目录包，不作为公开分发产物。

## 证据规则

- 真实站点仅执行登录和读取请求，凭据只在运行时内存、应用录入界面及平台安全存储中使用。
- 失败、失效、权限拒绝等破坏性分支使用本地 mock 或自动化，不对真实站点执行写操作。
- 下列截图均来自最终打包应用；自动化命令均在项目根目录执行。
- 本文件不记录账号、密码、Token、Cookie、完整 API Key 或完整敏感响应。

## E01-E24

| ID  | 清单项         | 证据与结论                                                                                                                                                                                                                                                                                                 |
| --- | -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| E01 | 启动           | 最终目录包使用干净隔离 userData 启动，无站点时进入站点录入；E2E 也覆盖首次启动。应用入口见本文顶部。                                                                                                                                                                                                       |
| E02 | 错误录入       | 本地 mock/E2E 覆盖无效地址、认证失败和核心能力失败；失败不会保存正式站点。真实账号未用于破坏性重试。                                                                                                                                                                                                       |
| E03 | 真实站点录入   | 通过最终打包 UI 依次录入两个真实站点，均完成登录、核心能力探测和保存；重启后仍存在。脱敏界面证据见 `02-overview.png` 与 `05-sites-settings.png`。                                                                                                                                                          |
| E04 | 安全凭据重启   | 同一隔离 userData 重启后可继续只读刷新；SQLite、凭据后端和扫描结果未发现明文秘密。凭据恢复使用 Electron `safeStorage`，未启用测试 secret codec。                                                                                                                                                           |
| E05 | 悬浮窗切站     | 最终打包悬浮窗可在两个站点之间循环切换并显示对应缓存/刷新结果，证据见 `06-floating.png`。                                                                                                                                                                                                                  |
| E06 | 窗口位置       | E2E 对真实 Electron BrowserWindow 执行移动、缩放、退出和重启，完整 bounds 恢复；主窗口初始为工作区宽 60%、高 90%，内部画布为 1440×1024。                                                                                                                                                                   |
| E07 | 多显示器       | 当前 Mac 只有一个显示器，无法执行物理拔除/恢复，标记不适用；显示器缺失时回退到主显示器可见区域由窗口恢复 E2E 覆盖。                                                                                                                                                                                        |
| E08 | 焦点与固定尺寸 | 悬浮窗使用 `showInactive()`、`focusable: false`、固定 380×260；最终打包截图 `06-floating.png` 无溢出，窗口配置和 E2E共同验证。                                                                                                                                                                             |
| E09 | 动态标题       | 两个真实站点实时余额分别覆盖高/低余额分支，查询中分支由本地状态覆盖；标题来自当前站而不是跨站总余额。见 `06-floating.png` 和领域测试。                                                                                                                                                                     |
| E10 | 默认 Key       | Key 策略单测覆盖今日请求最多、全零沿用历史、无历史首个有效、手动持久化；真实 UI 仅展示名称/脱敏标识，未显示完整 Key。                                                                                                                                                                                      |
| E11 | Key 失效       | 仅用本地 mock 验证手动 Key 失效后临时回退自动且不抹除手动偏好；未修改真实站点 Key。                                                                                                                                                                                                                        |
| E12 | 使用记录       | 最终打包应用展示真实站点统计和记录，证据见 `03-usage.png`；筛选、分页、排序、重置、列设置及 CSV 由 E2E覆盖。CSV `/tmp/sub2api-usage-test.csv` 权限为 0600、共 100 条数据、表头正确且无公式起始单元格。                                                                                                     |
| E13 | 渠道状态       | 两站列表与详情端点均为 supported；真实详情只出现基础字段，缺失延迟、Ping、可用率和时间线显示“待查询”，不使用静态假值。见 `04-channels.png`。                                                                                                                                                               |
| E14 | 全站总览       | 最终打包应用使用真实快照显示两站汇总、状态、缓存和更新时间，证据见 `02-overview.png`；聚合领域测试验证只统计有效缓存。                                                                                                                                                                                     |
| E15 | 后台刷新       | 调度器测试覆盖当前站优先、同站单飞、并发上限、抖动和退避；最终打包应用长时间运行时两站独立刷新，单站失败不会阻塞另一站。                                                                                                                                                                                   |
| E16 | 托盘关闭/恢复  | 最终包菜单栏显示 18×18 template 图标，证据见 `/tmp/sub2api-fullscreen.png`；托盘菜单模板和恢复回调由 `tray-icon.test.ts` 验证。Computer Use 无法接管 SystemUIServer 状态栏菜单，因此证据采用真机截图与生产回调测试组合。                                                                                   |
| E17 | 托盘退出       | 生产托盘菜单的退出回调调用统一退出路径，测试覆盖回调和菜单结构；最终收尾会停止隔离应用进程。SystemUIServer 自动化限制同 E16。                                                                                                                                                                              |
| E18 | 通知发送       | 本地受控状态验证低余额、去重、冷却和恢复，`notification-service.test.ts` 验证最终系统通知调用及脱敏内容；不向真实站点写入状态。                                                                                                                                                                            |
| E19 | 通知拒绝       | 为避免改变用户全局通知权限，拒绝场景不在当前真机修改系统设置，标记不适用；permission-denied 分支由本地受控测试覆盖。                                                                                                                                                                                       |
| E20 | 开机启动       | 当前产物按目标要求是未签名、未安装到 Applications 的内部目录包，不满足 macOS 13+ 登录项服务注册条件，标记不适用。已点击实际开关，UI 保持关闭，`sfltool dumpbtm` 无该应用条目，测试结束无系统残留。                                                                                                         |
| E21 | 删除站点       | 经行动时确认后，在隔离打包应用 GUI 中依次删除两个测试站点，其中一项完整执行二次确认；重启同一隔离 userData 后自动回到站点录入页。SQLite 中站点、凭据引用和快照均为 0，安全凭据后端条目为 0，凭据文件权限保持 0600。                                                                                        |
| E22 | Stitch 接收    | 五个业务 Screen 的 HTML 为第一视觉事实来源；最终正式运行没有 PreviewControls，也没有回退静态 UI 数据。截图见 `02-overview.png` 至 `06-floating.png`。                                                                                                                                                      |
| E23 | 安全审计       | 工作区、隔离 SQLite、credentials 文件、CSV 和稳定截图均已扫描，未发现账号密码、JWT、refresh token、Cookie 或完整 API Key。                                                                                                                                                                                 |
