# OpenCodex 使用记录、快速切换与全局动效设计

日期：2026-09-04
关联 PRD：[REQ-260904-usage-navigation-motion-PRD.md](../../../liran_docs/requirements/REQ-260904-usage-navigation-motion-PRD.md)
状态：已获用户确认，待生成实施计划

## 目标

本轮把 2.6.0 之后的三类体验问题收口：删除总览渠道推荐展示；修正 OpenCodex 使用记录的数据、缓存率和日期筛选口径；让 Sub2API 服务器、Radar、常用网站具备一致且即时的顶部快速切换；并为所有主页面建立克制、可访问、可验证的高级感动效。

## 范围与非目标

范围包括 Renderer 展示与交互、OpenCodex 日志归一化和筛选统计、三个嵌入模块的切换栏与状态反馈、局部 CSS 动画、测试和相关长期文档。

不重写 OpenCodex 服务端，不修改 `/api/logs` 协议，不改变 SQLite schema，不删除倍率查看/充值比例/渠道状态/手动关联，不改变嵌入网页的安全策略，不新增动画依赖，不复制截图中的远程后台菜单。

## 设计一：OpenCodex 数据口径

### 数据源与加载量

主进程继续请求本机 `http://localhost:10100/api/logs`，默认请求 `limit=4000`。服务端返回的 `total` 和实际 `logs.length` 都保留；当服务返回少于 4000 条时，界面显示真实加载数量，不能把请求上限当成实际数量。

### Token 归一化

对每条日志建立明确的数值字段：

- `rawInputTokens = usage.inputTokens`
- `cacheReadTokens = usage.cacheReadInputTokens ?? usage.cachedInputTokens`
- `cacheCreationTokens = usage.cacheCreationInputTokens`
- `realInputTokens = max(rawInputTokens - cacheReadTokens, 0)`
- `outputTokens = usage.outputTokens`
- `totalTokens = entry.totalTokens`，缺失时才用明细安全求和

展示和统计不得把缓存读取重复加到真实输入。缓存写入字段为真实的 `cacheCreationInputTokens`；缺失显示占位符，真实 0 显示 0。

### 性能字段

- 耗时使用 `durationMs`，显示秒并保留两位小数。
- 首字使用 `firstOutputMs`，显示秒并保留两位小数。
- t/s 优先使用日志 `displayMetrics.tokPerSecond.value`，缺失时才按现有安全降级规则处理。
- 不产生 NaN、Infinity 或负耗时。

对用户样例，预期归一化结果为：真实输入 3,003、输出 223、缓存读取 266,112、缓存写入 0、总 Token 269,338、耗时 11.37s、首字 8.14s、19.61 t/s。

### 缓存率

OpenCodex 表格在 Token 右侧加入“缓存率”列，复用 `src/renderer/shells/usage/cache-rate.ts` 的计算、格式化和颜色：

`cacheRead / (realInput + cacheRead + cacheCreation) × 100`

分母为 0 显示占位符；0 值保留为 0；列设置和表格可见列状态同步。

### 日期筛选

- 今天：本地时区当天 00:00:00 至当前时间。
- 近 7 天：含今天的 7 个本地自然日，从本地当天往前数 6 天的 00:00:00 开始。
- 近 30 天：含今天的 30 个本地自然日，从本地当天往前数 29 天的 00:00:00 开始。
- 自定义：开始日期含当天 00:00:00，结束日期含当天 23:59:59.999。

日期计算使用可注入时钟或等价确定性测试，覆盖跨日、跨月、本地时区和反向自定义区间。

## 设计二：删除渠道推荐展示

从总览删除面向用户的推荐渠道卡片、推荐文案、推荐状态和推荐区域占位。保留：

- 每站倍率查看 Popover
- 充值比例设置
- 倍率数据加载和缓存
- 渠道状态页
- 手动渠道关联
- 悬浮窗渠道摘要
- 倍率内部计算中仍有调用的评分/候选逻辑

若调查发现某个请求只服务已删除的可见推荐区域，才在实现计划中列为可安全移除项；否则保持后台能力，减少回归风险。

## 设计三：模块内快速切换

Sub2API 服务器、Radar、常用网站分别维护自己的条目集合，在各自嵌入网页工具栏顶部显示横向胶囊切换栏。当前项立即高亮并设置 `aria-current`；长名称单行省略，通过 title 和可访问名称提供完整文本。

点击流程：

1. Renderer 立即更新 active/loading 状态。
2. 主进程按稳定 ID 关闭或复用旧目标，并打开目标 WebContentsView。
3. 只允许当前模块一个视图挂载，旧视图不会与新视图叠加。
4. 以请求序列或目标 ID 丢弃过期响应。
5. 新目标打开成功后显示页面；失败时恢复旧目标或进入可重试错误态。

保留现有 `persist:` partition、同源导航白名单、Cookie 隔离、sandbox、contextIsolation、nodeIntegration=false 和 webSecurity。快速切换栏只切换本模块条目，不跨模块切换。

## 设计四：统一高级感动效

只使用现有 CSS/React 能力，不新增动画库。统一规则：

- 页面切换和卡片进入：160–240ms，淡入加轻微位移。
- 按钮、导航和控件：120–180ms，颜色、阴影和轻微位移/缩放。
- 弹层、通知和状态条：统一遮罩、淡入、缩放和可逆关闭。
- 刷新和加载：局部图标旋转或短骨架，避免整页闪烁。
- 成功/失败：图标、颜色和文本状态同时变化，不依赖动画传递唯一信息。
- `prefers-reduced-motion: reduce` 时移除位移、缩放和循环动画，保留必要的状态切换。

动画作用域限制在各页面/组件 CSS，不能通过全局规则覆盖嵌入网页、系统窗口或破坏现有固定尺寸。

## 错误与降级

- OpenCodex 令牌缺失、401/403、服务未启动、超时、非 JSON 和结构异常沿用现有错误态。
- 字段缺失显示“—”或既有占位，不猜测、不补造。
- 日志数量不足 4000 时按真实总数显示。
- 快速切换失败保留原页面优先，无法恢复时显示错误态和重试。
- 动画失败不影响按钮、键盘、表单、页面切换和数据刷新。

## 测试设计

### 单元与集成

- OpenCodex 归一化：缓存扣减、缓存读取/写入、总数、耗时、首字、t/s、缺失字段、负值和样例精确值。
- 缓存率：复用现有边界 0、30/31、60/61、85/86，并覆盖 OpenCodex 真实输入口径。
- 日期：当天 00:00、跨日、跨月、近 7/30 自然日、自定义端点和反向范围。
- 加载量：默认 4000、服务端少于 4000、total 与 logs 长度不一致。
- 推荐删除：总览不渲染推荐区域，但倍率 Popover、充值比例和渠道状态仍可用。
- 快速切换：立即 active、成功、失败恢复、过期响应丢弃、长名称和无条目状态。

### Electron E2E 与页面检查

- 三类嵌入页分别验证顶部快速切换、加载/错误态、无视图叠加、关闭和返回。
- 全部主页面验证导航、hover/press/focus、加载、刷新、弹层和通知反馈。
- 桌面窗口、窄窗口和 380×260 悬浮窗检查无重叠、无溢出、无固定尺寸回归。
- 使用减少动态效果配置验证核心操作仍可完成。
