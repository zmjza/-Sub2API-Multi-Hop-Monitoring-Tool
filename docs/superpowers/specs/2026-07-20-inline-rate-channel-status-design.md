# 倍率卡片内联渠道状态设计

## 目标

全部站点的倍率对比卡片无需点击即可显示每个最低倍率分组对应的渠道名称、状态、7 天可用率和时间线。并列最低分组分别匹配渠道；无匹配或歧义时明确降级，禁止回退到首个渠道。

## 数据流

1. 倍率分组出现后，按站点自动请求渠道列表，并复用页面会话缓存与站点级渠道弹窗缓存。
2. 每个最低倍率分组使用现有唯一匹配规则独立解析渠道；匹配成功后按 `siteId/channelId` 去重加载详情，详情并发上限为 4。
3. 列表快照用于五分钟稳定性评分和时间线；详情用于可信的 7 天可用率及更完整状态。旧世代响应和卸载后的响应不得写回当前视图。
4. 倍率比较候选保留站点级排行，但候选内部输出独立分组展示项。排序继续使用价格 60%、稳定 40%，不改变价格归一化公式。

## UI

每个站点候选内部按分组渲染紧凑信息带，不创建点击弹窗。信息带包含分组名、当前渠道、状态文字、7 天可用率、时间线和局部重试。加载、无数据、不支持、未匹配、歧义和失败均保持稳定高度。四个平台主题与固定顺序不变，平台容器始终单行横向滚动。

## 兼容边界

站点卡片原“查看渠道状态”入口继续展示完整渠道列表，并与自动加载共享缓存。不修改主进程接口、IPC 合约、认证、持久化数据、公共组件和全局样式；不新增依赖。

## 验证

以单元测试验证分组级匹配和排序，以协调器测试验证去重、并发、失败隔离和旧响应，以 Electron E2E 验证无需点击即可出现状态及完整渠道入口回归。最终执行 macOS 打包应用真机和正常/窄窗口截图检查，并按发布规则生成 1.3.4 双平台产物与校验和。
