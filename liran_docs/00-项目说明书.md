# Sub2API 多站监控项目说明书

## 2026-07-23 项目级增量

项目将在现有多站监控、使用记录、渠道状态、倍率比较和悬浮窗基础上增加普通用户 API 密钥管理，并把使用记录、全部站点和渠道监控统一到“每站当前生效 Key”口径。新增范围包括：API 密钥独立页面与远程分组切换、筛选后用量汇总、按所选 Key 的跨站指标、主窗口可见时的低频实时渠道轮询、结构化 Key-渠道关联和渠道健康区域去倍率化。

本轮已按用户决定跳过独立 UI 壳阶段，在唯一 `/goal` 中完成 UI、普通用户接口接线、测试、macOS 打包应用页面检查和双平台发布。功能版本为 `1.4.0`，当前修复版本为 `1.4.1`；真实证据包括 34 个 Vitest 文件/210 项、开发与最终安装副本 Electron E2E 6/6、两站可恢复分组写入、15 张页面截图、macOS bundle 严格签名校验和双平台结构审计。

成功标准新增以下硬边界：只使用普通用户 `/api/v1` 接口；完整 API Key 不离开主进程适配边界；远程分组写入必须回读确认；渠道轮询最低 30 秒并在非可见状态暂停；渠道关联优先使用分组 ID 的结构化关系；渠道健康 UI 不再展示折算倍率；完成后必须递增 SemVer、完成 macOS ARM64 真机与页面检查，并生成 macOS ARM64 DMG 与 Windows x64 NSIS，Windows 不冒充真机通过。

## 项目是什么

一款完全本地运行的 macOS/Windows 桌面应用，用于集中监控 6–20 个基于 sub2api 二开的中转站。应用通过普通用户账号登录各站，直接读取余额、API Key 倍率、今日用量、使用记录和渠道状态。

## 用户与问题

- 主要用户：同时使用多个 sub2api 中转站的个人开发者或小范围可信用户。
- 当前问题：余额、倍率、用量和渠道状态分散在多个站点，逐站登录耗时，难以及时发现低余额或渠道异常。
- 解决方式：常驻悬浮窗提供单站快照，主面板提供跨站汇总和完整明细，后台以受控频率刷新。

## 产品价值

1. 降低逐站登录和切换成本。
2. 将今日 Token、消费和余额放在持续可见的位置。
3. 通过低余额、渠道异常和连续失败通知降低服务中断风险。
4. 保持账号和数据完全本地，避免引入新的云端信任边界。

## 成功标准

- 用户能够添加并安全保存多个站点，失败站点不会误保存为可用。
- 悬浮窗可以稳定展示并切换站点，数据新鲜度和错误状态可辨认。
- 主面板能够正确汇总有效数据，并完整查询使用记录与渠道状态。
- 手动/自动默认 Key、倍率合并、时区边界、缓存和调度规则均有自动化测试。
- macOS 真机完成窗口、托盘、通知、Keychain 和主流程验收。
- Windows 能在 CI 中构建、启动并通过核心自动化测试，但不宣称真机通过。
- Stitch UI 以原始 HTML 为第一事实来源，完成控件规格盘点、实例级视觉复修和接收检查；本 Stitch 路线不执行 Product Design Design QA。

## 范围

- Electron 桌面外壳、悬浮窗、托盘、开机启动和通知。
- 本地站点凭据、偏好、缓存和能力矩阵管理；不提供常用账号模板。
- sub2api 认证、Token 续期、接口适配和多站调度。
- 总览、今日统计、使用记录、渠道状态和设置页面。
- 源码分发、双平台脚本、CI 与构建产物。
- Codex Radar 公开模型摘要页面；该页面不接入站点凭据、业务数据库或站点刷新链路。

## 不做

- 不使用 Playwright 登录站点。
- 不建设云端账号、同步或遥测服务。
- 不修改中转站业务数据。
- 不展示、记录或导出完整 API Key。
- 不做人民币换算、自动更新和密码导出。
- 不承诺兼容完全脱离 sub2api 协议的系统。

## 当前状态

`2026-07-24 API 密钥与监控联动 1.4.0 已收口，macOS 安装启动修复 1.4.1 已验证`。Electron + React + TypeScript + Vite 工程、API 密钥等六个主导航界面、sub2api 普通用户 HTTP 适配、认证与 Token 续期、SQLite、safeStorage、调度、缓存、通知、白名单 IPC 和本地 CSV 均有真实代码与自动化证据。两个授权站点完成分组写入、回读与恢复；第三站受 Turnstile 阻断，仅有用户现存会话的只读页面证据。macOS 页面检查沿用同功能基线，`1.4.1` DMG 和安装副本严格签名校验、LaunchServices 启动及安装副本 E2E 6/6 通过。Windows 只完成 x64 NSIS 交叉构建与结构检查，未真机；macOS 为完整 ad-hoc 签名，但不是 Apple Developer ID 签名且未公证。

主窗口使用无框外壳，初始占主显示器工作区宽 `60%`、高 `90%`，Renderer 响应式铺满窗口；`1440 x 1024` 仅为 Stitch 视觉参考，不是固定画布或缩放容器。悬浮窗为独立 `380 x 260` Renderer，可停靠四角。它保持已显示但不置顶，浏览器和其他前台应用可覆盖；macOS 台前调度/多 Space 下保持可见，不覆盖全屏应用。

## 2026-07-18 外发版合并规划

朋友版新增的 Radar、使用记录字段、渠道关系/请求协调和悬浮窗透明度已合并为 `1.1.0`，完成自动化、macOS 验收、页面检查和双平台产物构建。功能合并采用逐功能移植，保留主线非激活窗口、安全 preload、敏感数据和 macOS ARM64 发布边界。
