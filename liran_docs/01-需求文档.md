## 2026-07-24 1.4.2 总览额度与渠道唯一择优

- 全部站点不显示“按订阅规则”。有限额 Key 使用 `max(0, min(账号余额, quota - quota_used))` 并沿用 1.3.9 的额度进度 UI；quota 缺失、0 或无效代表无限额度，使用账号余额。
- 顶部“所选 Key 可用额度”把每个已解析站点的当前 Key 可用金额相加；未知站点不计入金额且不得伪造为 0。
- 严格 Key-渠道解析继续返回 matched/unmatched/ambiguous，供倍率比较维持唯一高置信门禁；总览遇到 ambiguous 时，只能在结构化候选集合内按语义、关系平台/模型和稳定性确定唯一最接近渠道，不得从集合外取值。
- 总览卡片、自动详情请求、刷新和重试必须共享最终渠道 ID；输入顺序变化不得改变结果。

### RQ-22 API 密钥管理与分组切换

- 左侧顺序固定为：全部站点、API 密钥、使用记录、渠道状态、站点管理、雷达。
- 页面复用全局当前站点，支持服务端分页、名称或脱敏摘要搜索、分组筛选、状态筛选和强制刷新；切站清空旧数据和筛选，刷新保留筛选。
- 表格字段为名称、脱敏 API Key、分组、平台、有效倍率、当前并发、今日实际消费、近 30 天实际消费、过期时间、状态和创建时间，默认创建时间倒序。
- 有效倍率优先级为用户专属倍率、Key 内嵌倍率、可用分组默认倍率；倍率 0 是有效值。
- 分组切换只允许当前用户可绑定分组；相同分组不请求；单行写入锁；`PUT /keys/{id}` 后必须 `GET /keys/{id}` 回读一致才成功，失败恢复原值。
- 首版不解绑、不批量、不创建、不删除，也不修改名称、状态、额度、有效期和限速。
- 今日消费使用批量接口并按 100 个 ID 拆批；近 30 天每日用量受控并发 3、单站缓存、单项失败隔离。缺失显示“待查询”，不伪造零值。

### RQ-23 使用记录自动筛选与汇总

- API Key、模型、分组、请求类型、计费类型、计费模式和有效日期范围变化后约 300ms 防抖自动查询，页码回到 1。
- `/usage` 与 `/usage/stats` 使用完全相同的筛选和时区；顶部总请求、总 Token、实际消费、平均耗时来自 stats，不使用站点快照或当前页估算。
- 查询时保留旧内容并使用局部刷新状态；AbortSignal 与请求世代共同防止旧结果覆盖；手动刷新、重置、当前筛选 CSV 继续可用。

### RQ-24 全部站点按当前 Key 汇总

- 手动模式使用用户所选 Key；自动模式使用实际生效 Key；无法确定时明确显示，不回退到整站统计。
- 顶部展示所选 Key 可用额度、今日 Token、今日消费；每卡展示脱敏 Key、分组、今日请求、Token、实际消费、可用额度和关联渠道。
- 有限额 Key 可用额度为 `max(0, min(账号余额, quota - quota_used))`；quota 缺失、0 或无效的无限额 Key 使用站点账号余额；订阅元数据不改变额度口径；不得重复累计同站账号余额。
- 每站按 `api_key_id` 查询 stats 后受控聚合，Key 或分组变化使旧快照失效。

### RQ-25 主窗口渠道低频实时监控

- 仅主窗口相关页面可见时轮询；悬浮窗、隐藏、最小化和后台暂停。恢复可见且缓存超过 30 秒时立即刷新。
- 支持 30/60/120 秒，默认 60 秒且禁止低于 30 秒；同站请求 single-flight，全局并发 2，多站错峰并加小幅抖动。
- 429 遵守 Retry-After；否则按 2/4/8/15 分钟退避；认证失效和 unsupported 停止该站轮询，成功后恢复常规周期。
- 周期只取概览；详情仅为当前查看或当前 Key 关联渠道按需读取；刷新保留旧数据并显示最后更新时间和倒计时。

### RQ-26 Key-渠道关联和健康状态修复

- 主链路为 `Key.group_id → groups/available → channels/available.groups[].id → 渠道 → monitor`；本地契约必须保留 groupId。
- 渠道到 monitor 优先规范化完整名称，再以平台、monitor.group_name 和模型交叉确认；旧站名称回退只能接受唯一高置信结果，多候选为“关联不明确”。
- 分离健康状态、请求同步状态、关联状态和数据新鲜度。只有远程明确 failed/error/down/unavailable 才显示异常。
- 从渠道页面、渠道弹层和关联渠道摘要删除 BadgePercent、倍率徽标、“倍率不可用”“折算 xx”“折算待设置”、tooltip、占位和无用局部样式。独立倍率比较、充值比例、底层倍率数据和接口保留。

### RQ-27 安全、回归与发布

- 只允许普通用户 `/api/v1`，禁止 `/admin/*`；完整 Key 只在主进程适配层短暂读取，Renderer、IPC、SQLite、日志、截图、fixture 均不得出现。
- 站点、Key、分组、渠道 ID 及写入负载在 IPC 使用固定白名单和 Zod；不修改密码、Token、safeStorage、认证续期和数据库安全方案。
- 后续开发按 TDD 覆盖单元、集成、Electron E2E、异步竞态、脱敏与旧功能回归；用户已授权 Codex 负责 macOS 打包应用真机和页面样式检查。
- 完成后递增 SemVer，更新 README、CHANGELOG 和坑点，构建 macOS ARM64 DMG 与 Windows x64 NSIS、更新 SHA-256；Windows 只记录交叉构建与结构验证。

### RQ-17 视觉与可访问性约束

- 应用只提供固定浅色模式，不提供深色、跟随系统或主题切换，也不需要持久化主题偏好。
- 视觉方向为克制的液态玻璃桌面工作台。玻璃材质只用于窗口外壳、侧边导航、顶部工具栏、悬浮窗和浮层，不得覆盖表格、表单、密集数据区、渠道时间线或危险操作区。
- 启用“减少透明效果”时，玻璃表面降级为高不透明实色面板并保留层级、边框和可读性；高对比度模式必须强化文字、边框、焦点和状态区分。
- 透明度和对比度降级不得改变既有业务状态优先级，也不得仅依赖颜色表达错误、缓存、选中或渠道健康。
- 当前 Stitch 产物为 5 个业务 Desktop Screen：全部站点、使用记录、渠道状态、悬浮窗、站点管理与设置，另有 1 个 Design System 资产。常用账号功能已取消，不属于任何 Screen 或 Tab。悬浮窗保留独立 Renderer。
- `1440 x 1024` 仅作为 Stitch 视觉参考尺寸。Electron 主窗口默认宽度为主显示器可用工作区的 `60%`、高度为 `90%`，自动居中且可从原生边缘和四角缩放；Renderer 必须响应式铺满当前内容区，不得使用固定画布缩放留下大面积空白。左侧导航固定于窗口内容区左侧，不随右侧页面滚动。
- 本 Stitch 路线不执行 Product Design Design QA；视觉门禁为 Stitch HTML 第一事实来源、控件规格盘点、实例级复修和接收检查。

## 关键业务规则

### RQ-28 在线更新

- 更新检查入口为启动时、设置页手动检查和主界面右上角版本徽标点击；三者复用同一主进程检查服务，避免 Renderer 自行请求 Gitee。
- 更新提示必须显示目标版本和真实更新说明，支持立即更新、跳过此版本和稍后提醒；跳过版本与提醒时间只能保存为非敏感本地设置。
- Windows 目标是下载 NSIS、自动安装并重启；当前只允许将其写成实现目标，必须通过真实 Windows 验收后才能写成完成。
- macOS 目标是检查、下载 DMG、打开 DMG，必要时手动替换；当前 ad-hoc、未公证条件下禁止写成可靠的静默自动替换。
- Gitee 是唯一发布源；稳定版只有一个通道，不引入 GitHub 或 beta。Gitee feed 兼容性未验证前必须标为待验证。
- 真机更新验证允许递增 patch 测试版本。测试版本不得改写业务功能，不得伪造功能更新说明，必须显示“真机更新测试专用”等明确文案。
- 更新必须保留 SQLite、safeStorage/Keychain/DPAPI、站点配置和应用设置；下载、校验或安装失败不能使当前版本不可启动。
- 禁止远程代码执行、上传站点凭据、修改后端 API、认证权限、支付或站点业务数据。

以下规则跨越多个页面和服务，是实现与验收时不能由单个模块自行改写的公共口径。

### 站点保存

- 登录、用户资料、Key 列表、倍率基础、今日统计和使用记录为核心检测链。
- 渠道监控为可选能力；缺失时记录 `unsupported`，不阻止保存。
- 失败项保留在编辑态，不进入后台刷新与总览。

### 默认 Key

- `manual` 模式永久保存用户选定 Key；失效时保留选择记录、提示用户并临时回退 `auto`。
- `auto` 模式每天按本机时区统计今日 `total_requests`，取最大值；平局使用稳定排序，避免来回抖动。
- 全部为零时沿用上次自动选择；无历史时使用第一个有效 Key。

### 数据新鲜度

- 缓存默认 2 分钟后标记过期；用户可选择 2、5、10 或 30 分钟，设置由 SQLite 持久化并用于所有站点的状态与汇总判断。
- 有效缓存可以计入总览并显示缓存标记；过期缓存不得计入汇总。
- 刷新失败不得删除最后一次成功数据。

### 既有余额/站点刷新调度（与 RQ-25 渠道调度独立）

- 启动后当前站首次刷新使用 2–30 秒抖动；后续当前站与后台站按用户选择的 1、5、10 或 15 分钟周期刷新，默认 5 分钟。
- 最大并发：1–4 站全并发；5–10 站为 4；11–20 站为 6。
- 同站接口间隔 100–500ms，手动刷新 5 秒防连点，失败退避为 30 秒、1、2、5 分钟并带抖动。

### 页面与窗口增量规则

> 以下为 2026-07-21 及更早版本的历史增量规则；其中整站汇总、名称关联和渠道倍率徽标相关内容已被本文顶部 RQ-24 至 RQ-26 覆盖，不再作为后续实现目标。独立倍率比较仍有效。

- 倍率推荐优先唯一匹配渠道并通过最近五分钟全 normal 硬门槛；无渠道状态的有效分组也参与候选但标记“无渠道状态/待核验”，不显示为稳定。歧义、异常、过期、未来、非法或请求失败不参与。合格候选使用 min-max 价格分，价格占 60%、稳定占 40%，每平台只显示第一名。

- 使用记录的站点、模型、分组和 Key 为真实下拉数据；每页最多 20 条，无“地区”字段，时间为本地 `MM月 dd日 HH时 mm分 ss秒`，增加思考等级，CSV 保留原始数值。
- 渠道列表超过 6 项时独立滚动，状态徽标靠近端点 PING；切站或切渠道先清除旧详情并显示真实加载态。
- 悬浮窗默认右上，支持左上、右上、左下、右下并持久化；`alwaysOnTop=false`，浏览器和其他前台应用可以覆盖。切换应用、窗口或台前调度组时不得自动最小化或隐藏，显示悬浮窗必须使用非激活显示，不得因常驻逻辑调用 `focus()`；macOS 可跨 Space 保持可见但不得覆盖全屏应用。启用悬浮窗时主窗口最小化会切换到悬浮窗；关闭悬浮窗时主窗口隐藏到托盘；主窗口关闭按钮真正退出应用。点击悬浮窗扩大按钮后隐藏悬浮窗并恢复、聚焦主窗口。
- 通知设置包含余额阈值、站点异常、渠道异常、恢复通知、5/15/30/60 分钟冷却和系统通知支持状态；通用设置包含开机启动、1/5/10/15 分钟刷新、悬浮窗开关与位置、2/5/10/30 分钟数据过期提示。

### 动态标题

- 余额 `>= 2`：`这么有钱，就使劲蹬 Codex，别浪费！💸`
- 余额 `< 2`：`快没钱了，赶紧充钱，别让天才程序员陨落！🥲`
- 未知/查询中：`正在查余额，先让 Codex 蹬一会儿… ⏳`
- 副标题固定：`Sub2API 多站监控`。

## 状态模型

所有主要查询视图至少支持：

- `idle`：尚未触发。
- `loading`：无缓存的首次查询。
- `refreshing`：已有数据的后台刷新。
- `partial`：部分能力成功、部分失败。
- `success`：本轮核心查询成功。
- `stale`：仅有过期缓存。
- `error`：无可用数据且查询失败。
- `auth-required`：自动续期和密码重登均无法完成。
- `unsupported`：站点未开放对应能力。

优先级：`auth-required/error > partial > stale > refreshing > success > idle`。有缓存时刷新动画不得遮挡核心数值。

## 非功能需求

- 安全：最小 IPC、敏感数据加密、日志脱敏、CSP 和导航限制。
- 性能：20 站后台运行不创建每站浏览器或渲染进程；主面板与悬浮窗复用统一数据源。
- 稳定：单站故障隔离，多显示器和缩放下窗口位置可恢复。
- 可用性：失败原因、缓存时间、覆盖率和能力缺失必须可见。
- 可维护：统一适配器和标准化模型，需求、任务、测试可追踪。
- 隐私：无云端、无遥测、无敏感信息导出。

## 2026-07-18 外发版功能合并增量

本节描述朋友版相对 1.0.0 主线的功能增量；已在 1.1.0 完成实现和验收，历史章节中的 1.0.0 证据仍保持不变。

### Codex Radar

- Radar 是正式主导航入口，页面显示公开模型摘要、评分、通过任务数、等价成本、耗时、推理等级、推荐用途和数据时间。
- Renderer 只向 `https://codexradar.com/current.json` 发起公开 GET；CSP 必须只放行该来源，不得使用通配符。
- 网络失败、HTTP 非 2xx、JSON 结构缺失或数据为空时显示可理解的错误/空态，并保留刷新入口；不得阻塞站点监控主链路。
- 外部数据只存在于页面运行时状态，不写入站点数据库、凭据存储、日志或导出文件。

### 使用记录增强

- 适配层、共享契约、IPC 和 UI 同步透传 `reasoning_effort`、缓存创建 Token 和请求耗时。
- 缺失字段使用明确的空值展示，不伪造默认耗时、倍率或推理等级；CSV 保留原始数值且继续执行脱敏和公式注入防护。

### 渠道关联与请求保护

- 使用 `/channels/available` 的平台、分组和模型关系辅助 Key 分组到渠道的唯一匹配；多候选或无法确认时不得强行绑定。
- 渠道列表按关联优先级和可用率排序，但保留用户可理解的稳定顺序。
- 站点、渠道和详情请求必须以站点 ID、渠道 ID 和请求序号校验迟到响应，禁止旧响应覆盖当前页面。
- 渠道自动刷新失败时保留可识别的旧状态/错误状态，不把旧对象伪装成当前对象。

### 悬浮窗透明度与跨平台

- 透明度范围为 `35%–100%`，默认 `84%`，设置持久化并在主进程原生窗口上立即生效。
- 透明度不能通过改变内容表面造成布局或文字对比度失真；减少透明和高对比度降级仍适用。
- macOS 和 Windows 都使用普通非置顶窗口层；macOS 继续遵守非激活显示与不覆盖全屏规则。

### 版本与验收

- 本次功能调整已递增至 `1.1.0`；macOS 构建 ARM64，Windows 构建 x64 NSIS。
- Codex 负责 macOS 真机和现有视觉方案页面检查；Windows 形成交叉构建、结构和自动化证据，不冒充 Windows 真机通过。
