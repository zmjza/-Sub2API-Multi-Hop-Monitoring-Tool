# 需求文档

## 2026-08-05 1.7.12 交互认证浏览器边界收口（当前有效）

- Cloudflare Turnstile 必须通过系统 Google Chrome 独立临时 Profile 由用户本人完成真实人机验证；应用不复制日常 Chrome Profile、Cookie、验证码结果或完整页面存储。
- GeeTest 继续使用临时隔离的官方 Electron 登录窗口，但不得改写 User-Agent、UA-CH、`navigator` 或通过 CDP 操作挑战 iframe；窗口使用原生浏览器标识和官方页面行为。
- 主进程仅读取目标 origin 的有限登录 Token 白名单；同源顶层导航、sandbox、contextIsolation、无 preload、核心接口校验、失败不落盘和取消/超时清理边界保持不变。

## 2026-08-04 1.7.3 交互认证与站点生命周期收口

- 官方交互登录成功只要求安全白名单中的 `access token`；`refresh token` 为可选字段，缺失时不得误判登录失败，也不得把凭据暴露给 Renderer。
- 官方临时窗口的同源顶层导航和重定向都必须拦截；跨域验证码 iframe 只能作为官方登录页子资源加载，不能被提升为顶层页面。
- 重新验证的任何持久化失败必须恢复旧 access/refresh token、认证 provider、快照、Key 缓存、Key 偏好、运行态、错误和耗时；删除站点必须清理快照、进行中的刷新、Key 用量缓存、通知规则和当前站点引用。

本节是 1.7.0–1.7.2 需求的收口补充，不改变 GeeTest/Cloudflare Turnstile 必须由用户本人在官方窗口完成的边界。

## 2026-08-04 1.7.2 渠道缓存回退与交互错误分类

- 登录接口无论返回 2xx 还是 4xx/5xx，只要安全白名单中的响应码或消息表明需要 GeeTest/Cloudflare Turnstile，都必须进入统一“需要完成安全验证”流程；不得把 2xx 错误包当作成功登录，也不得把 provider、Token 或原始响应透传到 Renderer。
- 渠道状态弹窗强制刷新失败时，必须继续展示最近一次成功的渠道列表、手动选中的渠道和已成功读取的详情；状态提示使用弹窗内的轻量 stale 状态和重试按钮，不能清空内容或要求重新打开弹窗才能恢复。
- 强制刷新期间只允许一次有效加载；选中渠道变化不得重新触发初始加载 effect。保存站点时安全存储或数据库任一写入失败，必须回滚站点、凭据、缓存和内存运行态。

## 2026-08-03 1.7.1 Turnstile Electron 兼容性补充（历史，已由 1.7.12 收口）

- 历史版本曾在官方交互登录窗口加载前移除 Electron User-Agent 标记。1.7.12 已撤销该逻辑：GeeTest 使用原生 Electron 标识，Turnstile 改由系统 Google Chrome 承接；安全边界和临时会话模型保持不变。
- 本补充不改变官方挑战、临时 session、同源顶层导航、Token 白名单和核心接口校验边界。不得复制 Chrome Cookie、验证码令牌、页面内容或完整 localStorage，也不得以脚本代做、破解或绕过挑战。
- 真实复测若仍出现 challenge iframe 未加载、挑战域 `ERR_CONNECTION_CLOSED` 或服务端验证失败，必须记录为外部 Cloudflare/Electron 网络兼容性阻塞，保留“受阻”状态并等待用户本人在官方窗口完成验证；不能把失败降级为普通“站点地址无效”。

## 2026-08-03 1.7.0 交互安全验证、重复站点与状态通知（当前有效）

本轮需求统一覆盖 GeeTest、Cloudflare Turnstile 两种交互式人机验证，以及站点重复添加、统一状态通知和渠道状态持续展示。普通密码登录、现有站点刷新、倍率比较、Key 管理和独立系统通知的既有口径继续有效。

### RQ-29 交互式登录验证

- 点击“添加并验证”后先读取公开设置；识别到 `geetest_enabled=true` 或 `turnstile_enabled=true` 时，不直接提交密码登录，显示统一对话框：标题“需要完成安全验证”；正文“该站点已启用 GeeTest。请在官方登录窗口完成人机验证，验证成功后将自动继续添加站点。”其中验证提供方名称按实际情况显示 GeeTest 或 Cloudflare Turnstile；按钮固定为“暂不添加”“开始登录”。
- 检测、等待、取消、超时、成功和失败全部使用统一应用内状态通知；不再把 `Error invoking remote method`、IPC 名称、堆栈或原始站点错误直接显示在表单下方。表单字段错误仍保留在字段附近，任务状态使用右上通知。
- “暂不添加”、Escape、关闭对话框或官方窗口取消均保留原表单内容且不保存站点；重复点击不能创建多个验证窗口。成功后才继续核心 profile、Key、分组、倍率、今日统计和使用记录验证，核心验证失败不得保存半成品。
- 官方登录窗口为原生模态 Electron 子窗口，使用临时 session、sandbox、contextIsolation、无 preload、严格同源顶层导航和有限 Token 白名单。Token 必须经主进程核心接口验证后才写入安全凭据库；验证码结果、Cookie、页面内容、密码和 Token 不进入 Renderer、SQLite、日志、截图或文档。
- 交互认证站点的 refresh 失效后进入 `auth-required`，禁止后台静默密码重登或自动弹窗；用户从站点卡片主动“重新验证”后更新原站点会话，不新建站点。重新验证失败保留旧凭据和旧业务缓存。

### RQ-30 重复站点身份规则

- 站点地址按现有 URL 规范化后比较；同地址、同用户名拒绝添加；同地址、不同用户名允许添加。邮箱用户名比较忽略大小写并去除首尾空格，非邮箱用户名仅去除首尾空格并保留大小写。
- 重复检查在发起登录前执行一次，在核心验证完成、正式保存前再次执行一次，覆盖并发添加窗口。凭据读取失败时不得猜测身份，必须安全失败并提示先检查凭据。
- 每个站点以独立 `siteId` 隔离凭据、Token、缓存、Key 偏好、统计、刷新状态、通知指纹、渠道关系和删除行为；列表提供安全脱敏账号标签用于区分同地址不同账号。

### RQ-31 渠道状态与统一通知

- 手动选择的渠道和已成功读取的渠道摘要必须持续显示。自动轮询采用 stale-while-revalidate：刷新中保留旧数据，失败显示“更新失败，显示上次数据”和最后成功时间；只有首次加载失败才显示完整错误态。重新打开“查看渠道状态”只能触发刷新或命中缓存，不能成为恢复数据显示的必要条件。
- 渠道列表、详情、关联关系、健康状态和新鲜度按 `siteId`/`channelId` 隔离；旧响应不得覆盖新站点、新关联或强制刷新结果。后台轮询失败不弹全局通知，避免重复打扰。
- 所有短暂操作反馈复用单一通知 Provider/Queue/Viewport，支持 loading、success、info、warning、error，稳定 ID 原位更新、最多三条、可关闭、键盘可达、aria-live 和 reduced-motion；继续保持固定浅色视觉、约 8px 圆角和窄窗口不溢出。

### 统一验收门禁

普通站点和两种交互验证均不得回归；取消、超时、无效 Token、核心接口失败、重复账号、同地址不同账号、通知迁移、渠道两轮自动轮询、macOS Apple Silicon 页面和 Windows x64 交叉构建均需有自动化或明确证据。Windows 交叉构建不等同 Windows 真机通过，真实验证码只能由用户本人在官方窗口完成。

## 2026-08-07 1.9.0 精确 Key-渠道关联与双推荐（当前有效）

- 主关系固定为 `Key.group_id → /channels/available.platforms[].groups[].id` 的精确相等；分组名和渠道名不同也必须能够关联，禁止用名称相似、前后缀、模型或 monitor ID 猜测。
- 一个 `group_id` 可对应多个渠道，最终关联值为 `channelId[]`；总览卡片显示全部最终渠道，渠道详情、状态刷新、重试和倍率推荐复用同一个最终解析器。
- 自动关系状态分为 `complete/partial/empty/error`。只有 `complete` 才能接管旧手动关系；`partial/empty/error` 保留手动关系。持久化键为 `siteId + groupId`，站点之间完全隔离。
- 渠道页面支持当前站点当前 Key 分组的多选、保存、修改、清除和恢复自动匹配；保存失败、空态和 loading 必须明确反馈。
- 稳定窗口为最近 1 分钟。`failed/error/down/unavailable` 不稳定；`degraded/unknown/空状态` 按稳定处理。没有关联渠道的候选与“已关联但状态 unknown/空”的候选必须区分。
- 综合分为 `价格分 × 60% + 稳定分 × 40%`。每个渠道独立计算；第一条推荐取有渠道状态候选的最高综合分，第二条取无渠道状态候选的最低价，两个候选池独立归一化。

## 2026-07-24 1.4.2 总览额度与渠道唯一择优

- 全部站点不显示“按订阅规则”。有限额 Key 使用 `max(0, min(账号余额, quota - quota_used))` 并沿用 1.3.9 的额度进度 UI；quota 缺失、0 或无效代表无限额度，使用账号余额。
- 顶部“所选 Key 可用额度”把每个已解析站点的当前 Key 可用金额相加；未知站点不计入金额且不得伪造为 0。
- 严格 Key-渠道解析继续返回 matched/unmatched/ambiguous，供倍率比较维持唯一高置信门禁；总览遇到 ambiguous 时，只能在结构化候选集合内按语义、关系平台/模型和稳定性确定唯一最接近渠道，不得从集合外取值。
- 总览卡片、自动详情请求、刷新和重试必须共享最终渠道 ID；输入顺序变化不得改变结果。

### RQ-22 API 密钥管理与分组切换

- 左侧顺序固定为：全部站点、API 密钥、使用记录、渠道状态、站点管理、雷达。
- 页面复用全局当前站点，支持服务端分页、名称或脱敏摘要搜索、分组筛选、状态筛选和强制刷新；切站清空旧数据和筛选，刷新保留筛选。
- 表格字段为名称、脱敏 API Key、分组、平台、有效倍率、当前并发、今日实际消费、近 30 天实际消费、过期时间、状态和创建时间，默认创建时间倒序。
- 有效倍率优先级为用户专属倍率、Key 内嵌倍率、可用分组默认倍率；倍率 0 是有效值。
- 分组切换只允许当前用户可绑定分组；相同分组不请求；单行写入锁；`PUT /keys/{id}` 后必须 `GET /keys/{id}` 回读一致才成功，失败恢复原值。
- 首版不解绑、不批量、不创建、不删除，也不修改名称、状态、额度、有效期和限速。
- 今日消费使用批量接口并按 100 个 ID 拆批；近 30 天每日用量受控并发 3、单站缓存、单项失败隔离。缺失显示“待查询”，不伪造零值。

### RQ-23 使用记录自动筛选与汇总

- API Key、模型、分组、请求类型、计费类型、计费模式和有效日期范围变化后约 300ms 防抖自动查询，页码回到 1。
- `/usage` 与 `/usage/stats` 使用完全相同的筛选和时区；顶部总请求、总 Token、实际消费、平均耗时来自 stats，不使用站点快照或当前页估算。
- 查询时保留旧内容并使用局部刷新状态；AbortSignal 与请求世代共同防止旧结果覆盖；手动刷新、重置、当前筛选 CSV 继续可用。

### RQ-24 全部站点按当前 Key 汇总

- 手动模式使用用户所选 Key；自动模式使用实际生效 Key；无法确定时明确显示，不回退到整站统计。
- 顶部展示所选 Key 可用额度、今日 Token、今日消费；每卡展示脱敏 Key、分组、今日请求、Token、实际消费、可用额度和关联渠道。
- 有限额 Key 可用额度为 `max(0, min(账号余额, quota - quota_used))`；quota 缺失、0 或无效的无限额 Key 使用站点账号余额；订阅元数据不改变额度口径；不得重复累计同站账号余额。
- 每站按 `api_key_id` 查询 stats 后受控聚合，Key 或分组变化使旧快照失效。

### RQ-25 主窗口渠道低频实时监控

- 仅主窗口相关页面可见时轮询；悬浮窗、隐藏、最小化和后台暂停。恢复可见且缓存超过 30 秒时立即刷新。
- 支持 30/60/120 秒，默认 60 秒且禁止低于 30 秒；同站请求 single-flight，全局并发 2，多站错峰并加小幅抖动。
- 429 遵守 Retry-After；否则按 2/4/8/15 分钟退避；认证失效和 unsupported 停止该站轮询，成功后恢复常规周期。
- 周期只取概览；详情仅为当前查看或当前 Key 关联渠道按需读取；刷新保留旧数据并显示最后更新时间和倒计时。

### RQ-26 Key-渠道关联和健康状态修复

- 主链路为 `Key.group_id → groups/available → channels/available.groups[].id → 渠道 → monitor`；本地契约必须保留 groupId。
- 渠道到 monitor 优先规范化完整名称，再以平台、monitor.group_name 和模型交叉确认；旧站名称回退只能接受唯一高置信结果，多候选为“关联不明确”。
- 分离健康状态、请求同步状态、关联状态和数据新鲜度。只有远程明确 failed/error/down/unavailable 才显示异常。
- 从渠道页面、渠道弹层和关联渠道摘要删除 BadgePercent、倍率徽标、“倍率不可用”“折算 xx”“折算待设置”、tooltip、占位和无用局部样式。独立倍率比较、充值比例、底层倍率数据和接口保留。

### RQ-27 安全、回归与发布

- 只允许普通用户 `/api/v1`，禁止 `/admin/*`；完整 Key 只在主进程适配层短暂读取，Renderer、IPC、SQLite、日志、截图、fixture 均不得出现。
- 站点、Key、分组、渠道 ID 及写入负载在 IPC 使用固定白名单和 Zod；不修改密码、Token、safeStorage、认证续期和数据库安全方案。
- 后续开发按 TDD 覆盖单元、集成、Electron E2E、异步竞态、脱敏与旧功能回归；用户已授权 Codex 负责 macOS 打包应用真机和页面样式检查。
- 完成后递增 SemVer，更新 README、CHANGELOG 和坑点，构建 macOS ARM64 DMG 与 Windows x64 NSIS、更新 SHA-256；Windows 只记录交叉构建与结构验证。

## 关键业务规则

### RQ-28 在线更新

- 更新检查入口为启动时、设置页手动检查和主界面右上角版本徽标点击；三者复用同一主进程检查服务，避免 Renderer 自行请求 GitHub。
- 更新提示必须显示目标版本和真实更新说明，支持立即更新、跳过此版本和稍后提醒；跳过版本与提醒时间只能保存为非敏感本地设置。
- Windows 目标是下载 NSIS、自动安装并重启；当前只允许将其写成实现目标，必须通过真实 Windows 验收后才能写成完成。
- macOS 目标是检查、下载 DMG、打开 DMG，必要时手动替换；当前 ad-hoc、未公证条件下禁止写成可靠的静默自动替换。
- GitHub 是唯一安装包发布源；Gitee 只做源码镜像。稳定版只有一个通道，不引入 beta。1.4.6 Gitee 资产是历史验证证据，后续版本使用 GitHub Release。
- 真机更新验证允许递增 patch 测试版本。测试版本不得改写业务功能，不得伪造功能更新说明，必须显示“真机更新测试专用”等明确文案。
- 更新必须保留 SQLite、safeStorage/Keychain/DPAPI、站点配置和应用设置；下载、校验或安装失败不能使当前版本不可启动。
- 禁止远程代码执行、上传站点凭据、修改后端 API、认证权限、支付或站点业务数据。

以下规则跨越多个页面和服务，是实现与验收时不能由单个模块自行改写的公共口径。

### 站点保存

- 登录、用户资料、Key 列表、倍率基础、今日统计和使用记录为核心检测链。
- 渠道监控为可选能力；缺失时记录 `unsupported`，不阻止保存。
- 失败项保留在编辑态，不进入后台刷新与总览。

### 默认 Key

- `manual` 模式永久保存用户选定 Key；失效时保留选择记录、提示用户并临时回退 `auto`。
- `auto` 模式每天按本机时区统计今日 `total_requests`，取最大值；平局使用稳定排序，避免来回抖动。
- 全部为零时沿用上次自动选择；无历史时使用第一个有效 Key。

### 数据新鲜度

- 缓存默认 2 分钟后标记过期；用户可选择 2、5、10 或 30 分钟，设置由 SQLite 持久化并用于所有站点的状态与汇总判断。
- 有效缓存可以计入总览并显示缓存标记；过期缓存不得计入汇总。
- 刷新失败不得删除最后一次成功数据。

### 既有余额/站点刷新调度（与 RQ-25 渠道调度独立）

- 启动后当前站首次刷新使用 2–30 秒抖动；后续当前站与后台站按用户选择的 1、5、10 或 15 分钟周期刷新，默认 5 分钟。
- 最大并发：1–4 站全并发；5–10 站为 4；11–20 站为 6。
- 同站接口间隔 100–500ms，手动刷新 5 秒防连点，失败退避为 30 秒、1、2、5 分钟并带抖动。

### 页面与窗口增量规则

> 以下为 2026-07-21 及更早版本的历史增量规则；其中整站汇总、名称关联和渠道倍率徽标相关内容已被本文顶部 RQ-24 至 RQ-26 覆盖，不再作为后续实现目标。独立倍率比较仍有效。

- 倍率推荐优先唯一匹配渠道并通过最近三分钟全 normal 硬门槛；无渠道状态的有效分组也参与候选但标记“无渠道状态/待核验”，不显示为稳定。歧义、异常、过期、未来、非法或请求失败不参与。合格候选使用 min-max 价格分，价格占 60%、稳定占 40%，每平台只显示第一名。
- OpenAI、Claude、Gemini、Grok 固定前四列且首屏完整可见，第五平台起单行横向滚动。平台识别不能只信 `group.platform`，必须结合名称、实际模型、说明和结构化关系。
- 全部站点每卡自动显示当前生效 Key 的渠道摘要；渠道页面和快捷弹窗显示每个渠道自身的折算倍率徽标。站点 footer 固定底部，倍率徽标、充值比例和两个查看入口不得错位或重叠。
- 全部站点只显示真实汇总与站点结果，不保留悬浮窗预览或固定“正在获取余额”；Token 统一按 K/M 缩写，倍率按用户费率、Key 内嵌分组费率、可用分组默认费率顺序解析，缺失显示“倍率不可用”。
- 使用记录的站点、模型、分组和 Key 为真实下拉数据；每页最多 20 条，无“地区”字段，时间为本地 `MM月 dd日 HH时 mm分 ss秒`，增加思考等级，CSV 保留原始数值。
- 渠道列表超过 6 项时独立滚动，状态徽标靠近端点 PING；切站或切渠道先清除旧详情并显示真实加载态。
- 悬浮窗默认右上，支持左上、右上、左下、右下并持久化；`alwaysOnTop=false`，浏览器和其他前台应用可以覆盖。切换应用、窗口或台前调度组时不得自动最小化或隐藏，显示悬浮窗必须使用非激活显示，不得因常驻逻辑调用 `focus()`；macOS 可跨 Space 保持可见但不得覆盖全屏应用。启用悬浮窗时主窗口最小化会切换到悬浮窗；关闭悬浮窗时主窗口隐藏到托盘；主窗口关闭按钮真正退出应用。点击悬浮窗扩大按钮后隐藏悬浮窗并恢复、聚焦主窗口。
- 通知设置包含余额阈值、站点异常、渠道异常、恢复通知、5/15/30/60 分钟冷却和系统通知支持状态；通用设置包含开机启动、1/5/10/15 分钟刷新、悬浮窗开关与位置、2/5/10/30 分钟数据过期提示。

## 状态模型

所有主要查询视图至少支持：

- `idle`：尚未触发。
- `loading`：无缓存的首次查询。
- `refreshing`：已有数据的后台刷新。
- `partial`：部分能力成功、部分失败。
- `success`：本轮核心查询成功。
- `stale`：仅有过期缓存。
- `error`：无可用数据且查询失败。
- `auth-required`：自动续期和密码重登均无法完成。
- `unsupported`：站点未开放对应能力。

优先级：`auth-required/error > partial > stale > refreshing > success > idle`。有缓存时刷新动画不得遮挡核心数值。

## 非功能需求

- 安全：最小 IPC、敏感数据加密、日志脱敏、CSP 和导航限制。
- 性能：20 站后台运行不创建每站浏览器或渲染进程；主面板与悬浮窗复用统一数据源。
- 稳定：单站故障隔离，多显示器和缩放下窗口位置可恢复。
- 可用性：失败原因、缓存时间、覆盖率和能力缺失必须可见。
- 可维护：统一适配器和标准化模型，需求、任务、测试可追踪。
- 隐私：无云端、无遥测、无敏感信息导出。

- 数据字段：稳定 ID、名称、规范化 HTTPS 根地址、可选登录页识别规则、最多 5 个快捷入口、非敏感登录状态、创建/更新时间、独立持久化分区标识。
- 名称和规范化地址不得重复；禁止用户名密码 URL、HTTP 降级和 `file/data/javascript` 等危险协议。
- 卡片视觉与 Radar 和现有浅色工作台一致，展示名称、域名、登录状态和快捷入口；卡片主体、编辑、删除、快捷入口为同级交互元素，禁止嵌套 button。
- 快捷入口最多 5 个，卡片不显示删除；编辑弹窗允许新增、修改、删除、排序。快捷入口保存名称、同源相对路径和可选 Lucide 预设图标，只能导航到当前服务器 origin。
- 新增、编辑、删除弹窗必须有行内校验、提交防重、Esc、遮罩关闭、焦点陷阱、关闭后焦点恢复和长文本防溢出；删除需应用内确认，并清理条目、当前视图及该服务器 Cookie、LocalStorage、IndexedDB、Cache Storage 和缓存。
- 仅修改名称或快捷入口时保留登录态；更换 origin 时清理旧会话；提供“清除登录状态并重新登录”。

### RQ-39 持久化内嵌网页登录

- 每个服务器使用基于稳定 ID 的独立 `persist:` Chromium partition，应用重启后保留网页登录态，服务器之间完全隔离。
- 远程视图保持 sandbox、contextIsolation、nodeIntegration=false、webSecurity=true、不注入项目 preload、不开放业务 IPC、不允许额外 webview、危险协议或任意跨域顶层导航。
- 左侧导航和顶部工具栏始终可见；内嵌工具栏提供返回、前进、主页、刷新、关闭，按钮状态正确；Esc 可关闭；主窗口 resize 后同步 bounds，不覆盖侧栏/工具栏/留空白。
- 登录状态规则：第一次打开登录页只显示“请登录”；曾成功进入登录后页面，之后被同源登录路由、明确认证重定向或可靠同源主页面 401/403 带回登录页，才标记“登录过期”并发送应用内提醒；普通图片或子请求 401 不得误报；重新登录成功自动恢复；判断不可靠显示“状态未知”。
- 应用不得保存网页密码、导出 Cookie/Token，不得把完整敏感 URL、网页存储和表单内容写入日志、文档、截图及测试夹具。

### RQ-40 站点 favicon

- 统一单个密码添加、批量添加、GeeTest 和 Turnstile 交互添加成功后的元数据抓取；核心验证成功并安全保存后才抓取。
- 复用同源安全链：读取合法 icon/shortcut icon/touch icon 候选，失败回退同源 `/favicon.ico`；限制同源重定向、超时、HTML 与图片字节数、MIME，并转受限 Data URL 持久化；禁止第三方 favicon 聚合服务。
- 批量成功项尽快携带站点摘要、名称和 icon 更新任务卡片，不等整批完成；卡片与详情左上角显示固定尺寸真实 icon，失败用现有地球占位。
- 历史站点缺少 icon 时提供受控的一次性后台补抓，限制并发并记录尝试状态，避免每次打开重复请求；抓取失败不阻塞站点使用。

### RQ-41 无渠道推荐过滤

- 全部站点“无渠道状态”最低价候选按 API/分组名称经 NFKC 和大小写规范化，只要包含“生图、停用、禁止、image2、图片”任一字段就不得参与推荐。
- 只检查名称；有真实渠道状态的候选逻辑不因该过滤误删；全部被过滤时显示无符合条件推荐，不得回退禁用候选。

### RQ-42 渠道状态时间线修复

- 全部站点卡片渠道时间线过滤无效及未来时间，按 checkedAt 旧到新排列，只保留可完整显示的最近记录，最右格必须是最新状态，不能被 overflow 截掉。
- 顶层状态与最近一分钟有效时间线冲突时，使用最新可靠记录；最近一分钟只有 normal/degraded 时不得显示异常；存在真实 failed/error/down/unavailable 时继续判异常；无近期证据时保持未知或过期。

### RQ-43 悬浮窗与菜单修复

- 自动或手动刷新遇到认证失效时统一提示“登录过期，请去站点管理重新验证”，可附站点名；使用稳定通知 ID 防止堆叠，保留最近成功数据，重新验证成功后清除过期展示。
- 悬浮窗主渠道卡片和关联渠道弹框由 12 格改为固定 20 格，旧到新排列，记录不足只在左侧补空；文案仍为“近 12 次可用 xx%”，百分比仅按最新 12 条真实有效记录计算，补空不进分母；无记录显示“暂无渠道记录”；固定 380×260 内不得与指标或页脚重叠。
- 悬浮窗余额必须保持当前实际 Key 口径；同一 Key 刷新保留最近可信余额；Key 未解析、切换中、加载失败或无可信值时显示 `—`，禁止回退并闪现站点总余额，禁止旧 Key 数值串到新 Key。
- 调转菜单映射：“通知”使用铃铛并进入通知规则页面；“设置”使用设置图标并进入通用设置页面；同步修正 shell 路由、预览、标题、单测、E2E、截图名称和旧文档中的相反描述。

## 2026-08-09 2.1.0 Sub2API 快捷入口菜单化

### RQ-44 新增服务器不再手填快捷入口

- 新增服务器弹窗只保留名称、HTTPS 根地址和可选登录页识别规则，不显示快捷入口名称、路径、图标、排序或逐条删除控件。
- 创建时快捷入口为空数组；保存并首次打开服务器后才具备菜单发现能力。

### RQ-45 绑定后从服务器真实菜单选择快捷入口

- 编辑已有服务器时提供“获取菜单”能力；主进程复用已打开的同服务器持久化分区视图，或在同 partition 的临时隐藏 `WebContentsView` 中加载服务器首页完成发现，成功后立即摘除。
- 菜单候选来自当前账号实际可见的语义导航区域，包括 `nav`、`aside`、`role=navigation`、侧栏/菜单容器及 SPA 链接；只接受与服务器 origin 相同的 HTTPS 目标，排除登录、注册、退出、外链、空链、危险协议和纯操作项。
- 菜单按“名称、路径、可选的上级菜单名、发现顺序”保存到按服务器隔离的 SQLite 设置键；图标由应用本地按菜单名称/路径映射到 Lucide，用户不需要选择图标。
- 编辑弹窗显示“快捷入口（已选 n/5）”和菜单复选框列表；勾选即加入，取消即移除，到达 5 个上限后未选项禁用，已选项仍可取消；顺序默认跟随服务器菜单顺序。
- 旧手工快捷入口按同源规范化路径与新菜单匹配；匹配成功自动显示为已选，匹配不到的显示在“当前菜单不可用”区域，可单独移除；未移除且保存时继续保留。
- 仅修改名称或快捷入口保留登录态；更换 origin、清除登录状态和删除服务器时同步清理对应菜单缓存。

### RQ-46 菜单发现状态与安全

- 未登录、登录过期、加载中、无可用菜单、发现失败和成功刷新都要有明确状态；登录过期提示“登录已过期，请重新登录后刷新菜单”，失败保留重试，不退回手工填写。
- 主进程只向 Renderer 返回最小非敏感菜单字段，禁止读取或传回 Cookie、Token、页面存储、完整 HTML、脚本和私有接口响应。
- 临时发现视图沿用 sandbox、contextIsolation、nodeIntegration=false、webSecurity=true、同源导航白名单、弹窗拦截和 extra webview 阻止；发现失败不改变已保存快捷入口或登录态。
- 菜单缓存按服务器 ID 隔离；服务器 origin 变更后旧菜单不再展示。
