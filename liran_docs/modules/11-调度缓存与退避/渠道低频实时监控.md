## 调度边界

渠道概览默认 60 秒，允许 30/60/120 秒，隐藏暂停。该周期不改变站点余额刷新、倍率刷新、悬浮窗 2 秒最近使用扫描或服务端真实探测周期。客户端只读服务端已有监控结果。

## 微观任务

- **CR-01 调度状态机**：目标是定义 idle/active/paused/backoff/auth-required/unsupported；输入为窗口可见性、surface 订阅和站点能力；文件为计划新增 `electron/main/services/channel-monitor-scheduler.ts` 与 `electron/main/services/channel-monitor-scheduler.test.ts`；边界为主进程单例；RED 覆盖无订阅、隐藏、恢复和销毁；步骤为 fake clock 状态测试后实现；验证定向测试；完成条件是无可见订阅时零请求；依赖无；禁止 Renderer 每卡建 timer。
- **CR-02 间隔与设置契约**：目标是校验 30/60/120 秒并默认 60；输入为用户选择与 app setting；文件为 contracts/storage migration-free setting/main tests；边界为不修改现有 refreshIntervalMinutes 语义；RED 覆盖 10/29/61 秒和旧配置缺失；步骤为严格 schema 与默认值；验证 contracts/storage；完成条件是旧安装安全获得 60；依赖 CR-01；禁止复用余额刷新字段。
- **CR-03 可见订阅桥接**：目标是主窗口 usage/overview/channels 相关视图报告订阅和 document visibility；输入为 App shell/window 事件；文件为 preload/main/App/tests；边界为悬浮窗永不订阅，卸载必释放；RED 覆盖切页、最小化、隐藏、恢复；步骤为 IPC 白名单、引用计数或集合；验证 App/main 测试；完成条件是订阅计数准确；依赖 CR-01/02；禁止传任意 channel ID 列表到调度器。
- **CR-04 列表 single-flight 与并发**：目标是同站合并、全局并发 2、多站错峰；输入为 `/channel-monitors` 读取函数；文件为 scheduler/loader/site-service/tests；边界为 siteId 分区与公平队列；RED 覆盖同站三请求、五站并发、慢站；步骤为队列测试后实现；验证 scheduler/loader 测试；完成条件是最大 active=2 且无重复；依赖 CR-01；禁止并发 4 的详情队列直接代替列表策略。
- **CR-05 抖动与恢复刷新**：目标是常规周期小幅随机错峰，恢复可见且缓存超过 30 秒立即刷新；输入为 clock/random/fetchedAt；文件为 scheduler/tests；边界为可注入随机源便于测试；RED 覆盖新鲜 29 秒、过期 31 秒和多个站；步骤为确定性 fake random；验证定向测试；完成条件是不会同步打爆多站；依赖 CR-04；禁止测试依赖真实等待。
- **CR-06 429 与失败退避**：目标是解析 Retry-After，否则 2/4/8/15 分钟退避并成功复位；输入为标准化 HTTP 错误；文件为 http-client/scheduler/tests；边界为认证与 unsupported 直接停、普通失败逐级；RED 覆盖秒/日期 Retry-After、连续失败、局部站点成功；步骤为错误分类和时钟测试；验证 http/scheduler 测试；完成条件是每站独立 nextAt；依赖 CR-01/04；禁止无上限重试。
- **CR-07 概览与详情缓存协同**：目标是周期只刷新列表，当前查看/关联渠道详情按需复用；输入为现有 RateChannelStatusLoader；文件为 loader/scheduler/App/tests；边界为列表 siteId、详情 siteId:monitorId，revision 隔离；RED 覆盖列表更新不触发全部详情、详情局部失败；步骤为 seed、force 和失效规则；验证 loader 测试；完成条件是弹层、页面、摘要共享结果；依赖 CR-04、CM 契约；禁止 N+1 详情轮询。
- **CR-08 UI 实时反馈**：目标是显示最后更新、倒计时、暂停/退避/刷新中且保留旧数据；输入为 scheduler view state；文件为 ChannelsPage、Overview、types、局部 CSS/tests；边界为状态不引发布局跳动；RED 覆盖 hidden pause、backoff、stale；步骤为组件状态测试后接线；验证页面测试和截图；完成条件是用户能区分实时健康与同步状态；依赖 CR-03..07；禁止刷新时清空全部卡片。

## 回滚点

调度器应有单一 enable 开关。出现封号风险时可关闭自动概览轮询并保留手动刷新、缓存展示和按需详情；不得通过提高所有站点刷新周期字段间接控制。
