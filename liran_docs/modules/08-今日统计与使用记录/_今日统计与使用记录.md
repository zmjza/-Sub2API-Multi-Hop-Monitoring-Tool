## 2026-09-04 REQ-260904-usage-navigation-motion 长期口径

- OpenCodex 日志通过 `/api/request-history` 的 cursor 分页读取当前范围全部记录；`/api/logs` 的 2000 条内存上限不再限制使用记录页面。
- 真实输入为 `max(inputTokens - cacheReadInputTokens, 0)`，兼容旧字段 `cachedInputTokens`；缓存读取、缓存写入、输出分别使用对应字段，缺失显示占位符，真实 0 保留。
- OpenCodex 缓存率复用中转站公式和颜色：缓存读取 /（真实输入 + 缓存读取 + 缓存写入）×100；Token 右侧显示独立缓存率列。
- OpenCodex 今天为本地当天 00:00 至当前时间；近 7 天/近 30 天为含今天的本地自然日。
- `durationMs`、`firstOutputMs` 和 `displayMetrics.tokPerSecond.value` 为性能展示优先来源；无效值不得产生 NaN/Infinity。

## 1.9.0 生成速度增量

- 请求表显示“耗时 / t/s”；t/s 使用原始 `outputTokens * 1000 / durationMs`，两位小数，不扣首字延迟。
- `<20` 慢、`20..<50` 正常、`>=50` 快；无效输入为不可用。最新记录同时提供给悬浮窗，不新增另一条高频轮询。

## 2.5.2 缓存率与 Token 展示

- 缓存率统一计算为 `cache_read_tokens / (input_tokens + cache_read_tokens + cache_creation_tokens) × 100%`；输出 Token 和费用不参与，分母为 0 显示 `—`，结果限制在 0–100%。
- Badge 颜色区间固定为 0–30 红、31–60 黄、61–85 绿、86–100 紫；中转站和 OpenCodex 共用纯函数和边界测试。
- Token 单元格独立显示输入、输出、缓存读取三项及图标；0 值保留，字段缺失显示 `—`，OpenCodex 未确认的缓存创建字段不猜测。

## 使用记录

- 当前站点使用真实下拉框；切站时清空旧站点记录、渠道、Key 和筛选枚举，避免旧数据冒充新结果。
- 模型来自 `/usage/dashboard/models`，分组来自 `/groups/available`，Key 来自 `/keys`；三类数据按站点和请求世代独立加载、独立合并，任一慢请求或失败不得阻塞或清空其他下拉数据。
- 每页固定请求并渲染最多 20 条，页面不使用纵向无限滚动；表格仅在列宽不足时横向滚动。
- 时间按用户本地时区显示为 `YYYY/MM/DD HH:mm:ss`；展示 `reasoning_effort` 思考等级，缺失显示 `—`。
- 总 Token 和行内 Token 使用 K/M 缩写，CSV 保留原始数值；不存在地区字段或地区操作。
- 筛选变化取消旧请求，防止迟到响应覆盖新结果。
- CSV 在本地从已获取/明确导出范围的数据生成，列顺序和脱敏规则可控。
- 完整记录不长期落库。
