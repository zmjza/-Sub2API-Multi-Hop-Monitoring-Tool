# 站点管理与首次引导

## 2026-08-05 1.7.9 Chrome 认证与账号归属

- Cloudflare Turnstile 直接打开系统 Google Chrome 独立临时 Profile；只读取同源有限 Token，真实 CAPTCHA 和登录仍由用户完成。
- 重新验证先比较 `/user/profile` 账号与保存用户名，不一致时返回 `SITE_ACCOUNT_IDENTITY_MISMATCH`，不覆盖旧站点。
- 同地址不同用户名允许重复站点，同地址同用户名拒绝；安全弹窗与统一通知在 720×520 页面检查中无溢出。

## 2026-08-04 1.7.8 Turnstile challenge 网络与退出

- 启动官方窗口前修复 Cloudflare challenge 域的 RFC 2544 假 IP/TLS 问题；真实挑战仍由用户本人完成。
- 安全提示框和官方登录窗口都支持关闭按钮与 `Esc`，取消、网络失败和超时不写入站点。

## 2026-08-04 1.7.7 官方窗口异步表单填充

- 官方登录窗口的 SPA 表单可能晚于页面 load 事件挂载；添加流程在同源页面内持续填充邮箱和密码，字段已有值时不覆盖。
- Turnstile/GeeTest 挑战仍完全由官方页面和用户操作负责；取消、Escape、关闭和失败不保存，取消后阶段恢复“等待开始”。

## 2026-08-04 1.7.3 交互会话与删除隔离收口

- 交互登录允许 access-only Token，官方窗口同时拦截同源顶层导航和重定向；重新验证失败恢复旧站点数据。
- 删除站点按 `siteId` 清理快照、刷新引用、Key 用量缓存、通知规则和当前站点引用，不影响同地址其他用户名。

## 2026-08-04 1.7.2 保存失败回滚与交互错误

- 2xx 登录错误包仍按 provider 进入官方验证窗口；普通成功响应才进入核心能力校验。
- 保存过程由串行队列保护，安全存储或数据库写入异常会清理站点、凭据、快照、Key/倍率缓存和运行态。

## 2026-08-03 1.7.0 双 provider 验证与重复站点（当前有效）

- 公开设置或登录错误识别 GeeTest/Cloudflare Turnstile 后，先显示统一“需要完成安全验证”对话框，再由官方登录窗口承接验证；取消、Escape、关闭和超时都不保存。
- 交互会话与密码会话最终汇入同一核心能力验证/保存门禁；`auth-required` 站点提供用户主动重新验证，不创建新站点。
- 同一规范化地址的同用户名拒绝、不同用户名允许；邮箱忽略大小写，账号标签安全脱敏，保存前后都做身份复核。

## 职责

完成首次启动引导、站点 URL 规范化、单站/批量验证及正式保存。覆盖 RQ-01、RQ-16。

## 叶子能力

录入链分为单站表单、批量解析和正式保存门禁，三者共享同一能力检测服务。

### 单站录入

- 输入站点名称、URL、账号和密码。
- URL 仅允许 HTTP/HTTPS；生产默认要求 HTTPS，HTTP 必须显式风险提示。
- “添加并验证”展示地址检查、登录、用户资料、Key、分组、使用记录和渠道能力阶段；完成后明确成功或失败原因。

### 批量录入

- 多行 URL 解析、去重和逐行错误提示；可用域名生成临时名称，单次最多 20 个。
- 显示 `当前数/总数` 和进度条；单项失败不得中断剩余验证，结束后统一列出成功、失败及安全错误原因。

### 保存门禁

- 核心能力失败不保存正式站点。
- 渠道监控缺失记录 unsupported，不阻断。
- 站点、凭据和能力矩阵必须事务式提交，失败不留下半成品。
