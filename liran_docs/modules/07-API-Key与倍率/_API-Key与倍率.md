## 职责

安全管理 Key 摘要并决定默认 Key 与最终倍率。覆盖 RQ-04、RQ-05。

## 规则

- 仅保存 Key ID、名称、脱敏标识、状态、groupId；不保存完整 Key。
- 自动选择按本机今日请求数降序；平局使用上次选择，其次稳定 ID 排序。
- 手动选择永久保存，失效时提示并临时回退，不能静默改写用户设置为 auto。
- 实际倍率优先级：`GET /groups/rates` 的当前用户分组倍率，其次 Key 内嵌 `group.rate_multiplier`，再次 `GET /groups/available` 的分组默认倍率；均缺失时显示“倍率不可用”，不得伪造。

## 2026-07-19 1.3.0 充值比例与可用分组倍率

- 每站点独立保存 `1:X` 充值比例，预设 1/5/8/10 并支持正数自定义；未设置显示“待设置”且排除跨站比较。

- 三站只读验证已确认 18/8/21 个分组可安全标准化；完整上游响应和认证信息不落盘。

## 2026-07-19 1.3.1 价格与稳定性综合排行

- 每站点、每平台继续只取有效分组中的最低折算倍率作为候选，价格分为 `min(10, 10 × 平台最低折算倍率 / 候选折算倍率)`。
- 稳定性只使用与候选分组唯一匹配的渠道：最近 5 分钟 normal=10、degraded=5、unknown/过期/空时间线=3、failed=0；无渠道或多匹配=5 并标“无渠道状态”。
- 综合分为价格 60% 加稳定 40%；平台内保留全部候选，按综合、稳定、价格、站点、分组和稳定 ID 排序。
- OpenAI、Claude、Gemini、Grok 顺序固定，其他平台稳定追加；三站只读复测的倍率分组数为 18/8/22。

## 2026-07-20 1.3.2 稳定性边界修复

- 最近五分钟时间线中的 unknown 现在固定判为“状态未知”3 分，不能被渠道汇总 normal 覆盖为稳定 10 分。
- 时间线有新鲜记录但当前汇总状态为 degraded/failed 时，分别保守映射为 5/0 分；没有新鲜时间点时仍判为未知 3 分。
- 评分公式、渠道唯一匹配、无渠道状态 5 分、平台顺序和 UI 布局不变。
