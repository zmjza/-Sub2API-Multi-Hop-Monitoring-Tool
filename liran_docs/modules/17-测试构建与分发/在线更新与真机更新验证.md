# 在线更新与真机更新验证

## 状态

核心代码已实现，按用户确认跳过独立 UI 壳路线，并直接在现有 Renderer 页面局部接入。本文件不代表 Gitee Release、Windows 自动安装或 macOS DMG 降级流程已经真实验证。

## 目标与范围

为现有 Electron 应用增加稳定版在线更新能力：启动时、设置页和主界面右上角版本徽标均可触发检查；发现新版本时显示版本号、更新内容、下载进度和错误状态；支持立即更新、跳过此版本和稍后提醒。Windows 尝试下载、安装并自动重启；macOS 在当前免费 ad-hoc 签名边界下检查、下载并打开 DMG，必要时由用户手动替换 App。

本需求不包含 GitHub、beta 渠道、付费托管、付费签名、公证、云同步、遥测、远程代码执行或站点业务接口改造。

## Gitee 发布与元数据

- Gitee Release 继续作为唯一发布渠道；是否能直接提供 electron-builder 所需 `latest.yml`、`latest-mac.yml`、安装包和 blockmap feed 仍待验证。
- 发布元数据必须通过 HTTPS 获取，版本、平台、架构、下载 URL、SHA-256、发布日期和更新说明必须相互一致。
- 更新说明来源为 `CHANGELOG.md` 和 Gitee Release 文案；不能从远程内容执行代码或读取站点数据。
- 稳定版只保留一个更新通道，不引入 beta 标记。

## 真机更新测试批次

允许发布递增 patch 版本，例如 `1.4.6`、`1.4.7`、`1.4.8`，只改变版本、构建产物和发布说明，不改变业务代码。每个测试版本的说明必须包含：`真机更新测试专用`、`本版本不包含业务功能变化`、`仅用于验证更新检查、下载、安装、重启和数据保留`。测试批次不得冒充功能发布；历史测试包需在 Gitee Release 或外部归档保留，不能用旧文件冒充当前版本。

## 数据、安全与回退

- 更新前后保留 SQLite、站点配置、应用偏好、safeStorage/Keychain/DPAPI 数据；不新增敏感数据上传路径。
- 跳过版本、稍后提醒时间和最近检查结果只能保存为非敏感设置。
- 下载校验、签名验证、版本比较和安装失败回退必须由主进程控制；Renderer 不直接下载或安装任意 URL。
- 关闭、退出、刷新、CSV 导出或站点写入进行中时，自动重启策略必须有明确行为；未知时标记待确认，不丢数据。
- 更新失败、网络中断、元数据损坏、版本回退、平台不匹配和磁盘不足均必须保留当前版本可启动。

## 现有页面接入范围

直接复用现有页面接入：右上角版本徽标可点击态、站点管理/设置页更新区、无更新/有更新/下载中/已下载/跳过/稍后/失败/平台降级/重启提示等状态；主进程通过 preload 预留 `check`、`download`、`install`、`openDmg`、`skip`、`remindLater`、进度事件和错误事件。本轮明确不创建空壳、不生成 Stitch 或 Product Design 提示词，不新增 `ui-shells` 文件。内部测试通过后，在同一条 `/goal` 继续执行可用平台的真实验收、问题修复和证据回写。
