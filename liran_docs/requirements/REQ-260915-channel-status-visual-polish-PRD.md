## 1. 产品/功能概述

统一优化渠道状态、API 密钥、使用记录、主导航动效和悬浮窗快捷导航，并补齐全部站点测试连通性反馈、站点快捷充值和三类内嵌页的安全外开。用户需要在不同入口看到一致的渠道状态分类和时间线口径，同时保留 V1/V2 各自真实指标；外部充值和新页面必须走系统浏览器，主程序保持可操作。

来源需求编号覆盖 REQ-1、REQ-2、REQ-3、REQ-4、REQ-5、REQ-6、REQ-7、REQ-8、REQ-9、REQ-10、REQ-11、REQ-12。任务标识为 REQ-260915、REQ-260915-channel-status-visual-polish；正式文档为 REQ-260915-channel-status-visual-polish-PRD。

## 2. 背景与问题

- 渠道状态不同入口仍存在 20 格、18 格和按 V2 时间窗变化的 24/14/30 格多套时间线口径。
- V1/V2 渠道卡片缺少统一的平台分类和可区分的平台识别图标，当前分类标多为同一绿色波形。
- V2 缓存率、可用率、首 Token 在窄布局中可能换行。
- API 密钥页只有密钥表格，无法在同一页面按平台查看当前渠道健康；分组下拉下方重复文字，名称列垂直偏上。
- 使用记录自定义范围只有日期，系统日期控件可能显示英文，不能选择小时。
- 页面和导航缺少明显、连贯的交互动效。
- 悬浮窗 Token/消费指标不能直接进入当前站点的使用记录。
- 全部站点测试连通性弹窗日志区偏静态，等待、成功、失败缺少可感知反馈。
- 站点卡片缺少一键打开已保存站点 `/purchase` 的充值入口。
- Sub2API 服务器、雷达、常用网站内嵌页对新窗口一律拒绝，用户主动安全链接无法外开。

## 3. 用户与使用场景

- 用户在渠道状态页按 OpenAI、Anthropic、Grok、Gemini、其他浏览 V1/V2 渠道。
- 用户在全部站点弹层和悬浮窗查看当前站点的紧凑渠道状态。
- 用户在 API 密钥页先查看某个平台的完整渠道卡片，再手动切换右侧 API Key 分组。
- 用户在使用记录页按中文日期和整点小时查询中转站或 OpenCodex 请求。
- 用户在悬浮窗双击今日 Token 或今日消费，进入当前站点的今日使用记录。
- 用户在全部站点卡片点击测试连通性，观察真实测试过程中的等待、成功或失败反馈。
- 用户点击站点卡片快捷充值，用本机 Chrome 或默认浏览器打开该站点 origin + `/purchase`。
- 用户在 Sub2API 服务器、雷达、常用网站中点击会打开新页面的安全链接，切到系统浏览器后仍能回到本应用。

## 4. 产品目标

1. 所有渠道状态视觉时间线统一为最近 18 格，数据和状态语义不被伪造。
2. V1/V2 和平台分类在主渠道页、全部站点弹层、API 密钥左侧、悬浮窗之间保持一致。
3. V1 和 V2 保留协议专属指标；同一视觉外壳不代表指标混用。
4. 使用记录两种模式支持中文、整点小时和真实时间边界。
5. API 密钥页在宽窄窗口都保持可读、可操作，不破坏既有密钥安全边界。
6. 新动效覆盖全站交互，同时支持减少动态效果降级。
7. 悬浮窗双击可准确携带当前站点和 Key 上下文进入使用记录。
8. 测试连通性弹窗以真实事件驱动明显、丝滑的状态反馈。
9. 站点快捷充值只打开已保存站点的 origin + `/purchase`，主程序保持可用。
10. 三类内嵌页允许用户手势触发的安全外开，同时继续拒绝危险协议、凭据 URL、非手势弹窗和认证窗口。

## 6. 当前项目事实

- 现有技术栈为 Electron + React + Vite，主窗口和悬浮窗均由现有 App/Renderer 入口管理。
- 现有渠道状态通过主进程适配器、站点级缓存、请求世代和 stale-while-revalidate 提供 V1/V2 载荷。
- 现有 API 密钥页、使用记录页、悬浮窗、主导航、全部站点卡片、测试弹窗和 IPC 契约已存在，本任务在其上增量改造。
- 主窗口最小宽度为 720px，API 密钥表格当前最小宽度约 1260px；悬浮窗固定 380×260。
- 测试连通性真实事件类型为 started、delta、completed、failed、cancelled；超时 30 秒后以 failed 和“测试超时”返回，不另增 timeout 事件名。
- 雷达视图、Sub2API 内嵌页、常用网站内嵌页当前 setWindowOpenHandler 一律 action: 'deny'；主窗口已对 https 外开系统浏览器。
- chromeExecutableCandidates 现用于认证 Chrome 探测；快捷充值只复用普通可执行文件探测，禁止带远程调试端口的认证会话。
- 相关真实文件见第 13 节影响范围和第 16 节关联文档索引。

## 7. 用户流程

用户打开或刷新页面 → 复用当前站点级渠道载荷 → 按平台分类渲染 V1/V2 卡片 → 在 API 密钥页按平台查看左侧完整渠道卡并在右侧手动切换分组 → 在使用记录页选择中文日期和整点小时 → 在悬浮窗双击 Token/消费后把站点、Key、今日范围传给主窗口 → 在全部站点卡片测试连通性并看到真实状态动效 → 点击快捷充值打开 origin + /purchase → 在 Sub2API/雷达/常用网站点击安全链接后于系统浏览器查看，再切回本应用 → Codex 使用源码 Electron 窗口完成 macOS 真机验证，再进行 macOS 打包冒烟。

## 8. 功能需求

### REQ-01 统一 18 格渠道时间线

触发条件：渠道状态页、全部站点弹层、API 密钥左侧渠道区或悬浮窗渲染渠道状态。
前置条件：站点级渠道载荷通过 schema 校验并包含可展示的 V1/V2 时间线数据。
用户操作：进入页面、切换站点、刷新或切换 V2 时间窗。
系统行为：按当前协议过滤、排序并裁剪最近 18 条，在不足时从左侧补空槽。
数据变化：只改变视觉展示窗口，不删除或改写底层历史数据。
状态变化：loading、success、stale、temporary error、empty 和 unknown 按现有状态机展示。
正常结果：所有渠道状态入口均显示 18 个可访问槽位。
异常处理：无效/未来时间和未知状态进入空槽或 unknown，不伪造健康记录。
禁止行为：不得继续使用 20 格或按 V2 时间窗显示 24/14/30 格。
对应 AC：AC-01

规则：

- 对应来源 REQ-1 及 REQ-2 的时间线数量口径。
- 固定显示 18 个槽位，真实记录按时间从旧到新排列，最新记录在最右侧。
- 记录少于 18 条时从左侧补灰色空槽；空槽不参与可用率计算，也不代表成功、降级或失败。
- 记录多于 18 条时只显示最新 18 条；底层缓存和请求可继续保留完整历史。
- V2 选择 90m、24h、7d、30d 时都显示 18 个槽位；时间窗只改变数据范围和桶间隔。
- 无效时间、未来时间和未知状态按现有过滤及 unknown 语义处理。
- 该规则只作用于渠道状态时间线，不改变使用记录图表或其他非渠道状态数据。
- 悬浮窗无障碍文案必须同步为近 18 次，不能继续写死最近 20 次。

### REQ-02 平台分类与图标

触发条件：渠道载荷完成归一化并准备渲染分类卡片。
前置条件：每个有效卡片至少有名称或可归入其他分类的来源字段。
用户操作：进入渠道页、切换分类或刷新站点。
系统行为：按别名归一化、固定顺序分组并生成图标/颜色映射。
数据变化：生成平台分类、数量、展示名称和排序结果，不修改上游名称。
状态变化：分类 loading、success、empty 跟随所属渠道载荷。
正常结果：五类分类头和数量稳定，真实名称同步显示。
异常处理：缺失/未知平台归入其他；空分类显示空态。
禁止行为：不得写死渠道清单或让所有分类复用绿色波形图标。
对应 AC：AC-02

分类顺序固定为：OpenAI、Anthropic、Grok、Gemini、其他。对应来源 REQ-3、REQ-4。

归一化：

- openai、open_ai、chatgpt 归 OpenAI。
- anthropic、claude 归 Anthropic。
- grok、xai 归 Grok。
- gemini、google、google_gemini 归 Gemini。
- 缺失或其他平台归其他。

展示：

- 分类头显示平台图标、平台名称和当前有效卡片数量。
- “其他”只有一个分类头；分类内卡片名称使用运行时获取的真实名称。
- OpenAI 使用绿色图标，Gemini 使用浅蓝色图标，Grok 使用深灰色图标，Anthropic 使用橙色图标，其他使用紫色图标。
- 各平台图标形状可以由实现选择，但必须有区分度、风格统一；状态颜色仍由正常/降级/失败/未知语义控制。
- 卡片除平台图标外保持统一视觉样式；现有状态边框、状态胶囊和状态文字保留。
- 主渠道页和 API 密钥左侧使用完整分类头与分类卡片网格；全部站点弹层和悬浮窗只显示紧凑摘要，不增加五个分类头。

### REQ-03 V1/V2 卡片与指标布局

触发条件：协议判断为 V1 或 V2 并进入卡片渲染。
前置条件：对应协议载荷和状态语义已由主进程归一化。
用户操作：查看、切换时间窗、点击卡片或调整窗口宽度。
系统行为：使用统一卡片外壳，按协议渲染专属字段和 18 格时间线。
数据变化：只读取对应协议指标，不将 V1/V2 字段互相填充。
状态变化：保留正常、降级、失败、未知以及 V2 健康/需关注/异常语义。
正常结果：V1/V2 指标可读，V2 三指标始终单行。
异常处理：缺失指标显示安全占位，不把缺失当成健康。
禁止行为：不得在 V1 卡片显示 V2 指标或在 V2 卡片显示 Ping/对话延迟。
对应 AC：AC-02

共同规则：

- 对应来源 REQ-2。V1/V2 卡片使用统一视觉外壳、图标容器、状态胶囊、间距和时间线形状；状态边框和状态文字语义保持现有规则。
- 记录格颜色语义不变，只优化形状、圆角、间距、尺寸比例和统一视觉语言。
- 卡片可读、可聚焦、长名称不撑破布局；渠道主页面沿用现有响应式网格，窄窗口可降为单列。

V1 卡片：

- 显示渠道名称、平台、用户倍率、状态、对话延迟、端点 Ping、可用率和 18 格 V1 时间线。
- 保留现有 7 天、15 天、30 天时间窗；时间窗只改变可用率/详情数据来源，不改变视觉时间线的 18 格数量。
- 不显示缓存率、首 Token 或 V2 矩阵指标。

V2 卡片：

- 显示渠道名称/分组、平台、用户倍率、状态、缓存率、可用率、首 Token 和 18 格 V2 时间线。
- 缓存率、可用率、首 Token 永远处于同一行三等分布局，无论窗口宽度如何变化都不能把其中一项折到下一行。
- 窄窗口优先缩小内部间距和数字字号；不得隐藏、缩写成无法识别的文案、换行或产生页面横向溢出。
- 不显示端点 Ping、对话延迟或 V1 探测条。
- 保留现有 90m、24h、7d、30d 时间窗；四个时间窗都固定显示 18 个矩阵桶。

### REQ-04 API 密钥页面渠道联动

触发条件：打开 API 密钥页、切换站点、切换平台分类或刷新。
前置条件：站点 Key 数据和共享渠道 loader/cache 可用。
用户操作：切换五个平台分类、滚动渠道区、复制 Key 或切换分组。
系统行为：宽窗口并排渲染渠道区与表格，窄窗口隐藏渠道区；分类只影响左侧。
数据变化：更新当前站点渠道展示和表格布局，不重复请求或修改分组。
状态变化：覆盖 loading、success、stale、temporary error、auth-required、unsupported、empty。
正常结果：完整卡片一行一个，表格保持可读且无页面级溢出。
异常处理：渠道失败保留过期缓存或显示明确错误，不回退到全部分类。
禁止行为：不得把完整 Key 放入渠道载荷，不得删除表格字段或自动写分组。
对应 AC：AC-03

布局：

- 对应来源 REQ-6、REQ-7。宽窗口显示“左侧渠道区 + 右侧 API 密钥表格”。
- 窄窗口真正隐藏渠道区，API 密钥区使用完整可用宽度；不得保留空白占位。
- 宽窄切换阈值由实际卡片宽度、表格可读性和窗口最小宽度 720px 计算，不要求用户记忆固定设备尺寸。

左侧渠道区：

- 顶部固定五个分类：OpenAI、Anthropic、Grok、Gemini、其他；不显示“全部”，首次默认 OpenAI。
- 分类切换只改变左侧渠道区，不自动过滤右侧 Key、不自动修改分组。
- 一行一个完整渠道卡片，卡片宽度等于渠道区可用宽度，纵向排列并在区域内部滚动；不做缩略卡片。
- V1/V2 复用渠道状态页完整卡片信息，但保留各自协议字段差异，不混用指标。
- 无当前分类数据时保留当前分类并显示空态，不自动跳转其他分类。
- 左侧区域复用站点级渠道状态 loader/cache，不在组件内建立重复请求链路。
- 覆盖 loading、success、stale、temporary error、auth-required、unsupported、empty 状态；失败有缓存时保留旧卡并标记过期。
- 左侧渠道卡片为只读展示；如需查看主渠道详情，使用明确的“查看渠道状态”入口，不能把整张卡片误当作分组操作。

右侧表格：

- 保留名称、API 密钥、分组、平台、有效倍率、当前并发、消费、状态、创建时间字段。
- 重新分配列宽；字段保持单行，空间不足时只允许表格容器内部横向滚动，页面本身不得溢出。
- 删除分组下拉框下方重复的分组名称文字。
- 名称列表头和内容水平、垂直居中。
- 不改变复制、脱敏、分组写入、失败回滚、分页和筛选语义。

### REQ-05 使用记录日期与小时筛选

触发条件：使用记录页选择自定义范围或修改日期/小时。
前置条件：当前模式为中转站或 OpenCodex，查询器和本地时区可用。
用户操作：选择开始/结束日期、整点小时、筛选、分页或导出。
系统行为：使用中文日期时间面板解析边界并把同一范围传给列表、统计和 CSV。
数据变化：更新查询条件、分页结果和统计样本；必要时主进程按 createdAt 做小时过滤。
状态变化：idle、loading、success、empty、error 和 invalid-range。
正常结果：两种模式均获得准确小时范围结果。

## 14. 验收标准

### AC-01 渠道时间线

对应需求：REQ-01、REQ-03
验收步骤：分别准备 0、1、17、18、19 条记录，切换 V1/V2 与 V2 四个时间窗，并在主渠道页、全部站点弹层、API 密钥左侧和悬浮窗检查槽位。
预期结果：每个入口始终渲染 18 个可访问槽位，真实记录靠右、最新在最右，缺失部分是左侧空槽，未知/未来记录不伪造健康状态。
失败条件：任一入口出现 20/24/14/30 格，最新记录不在最右，空槽被计入指标，或未来/未知记录被显示为成功。

### AC-02 分类与卡片

对应需求：REQ-02、REQ-03
验收步骤：使用四个平台别名、缺失平台和其他平台的夹具，检查五类顺序、数量、图标颜色、V1/V2 专属字段，并在宽窄窗口检查 V2 三指标。
预期结果：分类与别名一致，五类图标颜色正确，卡片外壳统一但指标不混用，V2 缓存率/可用率/首 Token 在所有支持宽度保持同一行且可读。
失败条件：分类顺序或颜色错误、其他平台丢失、V1/V2 指标互串，或 V2 指标隐藏、换行、造成页面溢出。

### AC-03 API 密钥页

对应需求：REQ-04
验收步骤：在宽窗口和窄窗口分别打开 API 密钥页，切换五类左侧分类，检查渠道卡片、表格滚动、重复文字、名称列对齐，并执行复制 Key 与分组写入回归。
预期结果：宽窗口显示左渠道区和右表格，窄窗口隐藏渠道区且无空白占位；渠道卡一行一个完整卡片；表格仅内部滚动；重复分组名消失、名称列水平垂直居中，原有写入与复制语义不变。
失败条件：窄窗口仍占用渠道区、页面级横向溢出、卡片缩略/换行、重复分组文字仍在、名称偏移，或 Key/分组业务回归。

### AC-04 使用记录

对应需求：REQ-05
验收步骤：在中转站和 OpenCodex 分别选择同日、跨日、只填一端、整点小时和反向范围，检查列表、统计、分页及 CSV。
预期结果：界面为中文日期时间面板；开始默认 00:00、结束默认 23:59:59；小时条件真实影响所有结果；反向范围阻止查询并显示中文错误。
失败条件：出现英文日期控件、分钟输入、结束日从 00:00 截止、小时只改显示不改数据，或列表/统计/分页/CSV 口径不一致。

### AC-05 动效与可访问性

对应需求：REQ-06
验收步骤：在菜单、页面、按钮、卡片、筛选、下拉、Tab、刷新、加载、成功、失败和空态之间操作，快速连续切换并启用 prefers-reduced-motion 检查焦点与请求次数。
预期结果：动效明显、连贯、无布局抖动；快速切换不重复请求/串数据；减少动态效果后仍有可见状态反馈且功能完整。
失败条件：动效不可感知或卡顿、改变请求顺序/焦点/滚动、触发重复请求，或减少动态效果后控件不可用。

### AC-06 悬浮窗快捷导航

对应需求：REQ-07
验收步骤：在悬浮窗双击今日 Token 和今日消费的完整指标块，分别覆盖主窗已打开、最小化、在其他页面和快速连续双击场景。
预期结果：主窗口被唤起并进入中转站使用记录，带入当前站点、当前有效 Key 和今日范围；旧请求不回写，悬浮窗仍为 380×260 普通窗口。
失败条件：跳到错误站点/Key、显示旧结果、双击只在数字字符有效、改变悬浮窗尺寸/置顶层级，或触发额外消费请求。

### AC-07 安全与跨平台

对应需求：REQ-08、REQ-10、REQ-11
验收步骤：扫描 Renderer 载荷、日志、截图、测试夹具和外部打开地址中的敏感字段，执行 macOS 源码窗口验收、macOS build/pack 冒烟和 Windows x64 交叉构建结构检查。
预期结果：完整 Key/Token/Cookie/原始 headers/敏感 URL 不出现在非安全边界；macOS 页面与 IPC 正常；Windows 仅记录交叉构建和结构验证证据。
失败条件：任一敏感字段泄露、macOS 白屏或 preload 断裂、Windows 被误写成真机通过，或旧缓存/请求世代安全规则回归。

### AC-08 测试连通性动效

对应需求：REQ-09
验收步骤：打开全部站点测试连通性弹窗，分别验证待开始、开始、等待、流式增量、成功、鉴权失败、30 秒超时、取消、关闭后迟到事件、无 Key/无模型和减少动态效果。
预期结果：各阶段都有与真实事件一致的可见反馈；运行中可取消且不能重复启动；迟到事件不改已关闭弹窗；完整 Key 不出现在日志；风险提示仍在。
失败条件：动画与真实结果不一致、超时被做成成功、取消后仍显示完成、泄露 Key，或减少动态效果后无法操作。

### AC-09 快捷充值

对应需求：REQ-10
验收步骤：对已保存 https 站点、尾斜杠、已含 /purchase、缺失网址、危险协议、凭据 URL、无 Chrome 回退、打开失败和快速连点分别点击快捷充值，并确认主程序仍可操作。
预期结果：合法站点打开 origin + /purchase；已含该路径不再重复追加；非法地址被拒绝并给出中文错误；Chrome 优先、否则默认浏览器；不改变站点/Key/渠道缓存。
失败条件：从卡片标题拼 URL、出现 //purchase、打开认证调试 Chrome、主程序被替换成充值页、或危险协议被放行。

### AC-10 系统浏览器新页面

对应需求：REQ-11
验收步骤：在 Sub2API 服务器、雷达、常用网站分别点击 target=_blank、window.open 和按钮跳转，覆盖安全 http/https、危险协议、非用户手势弹窗、打开失败，并验证原内嵌页返回/前进/刷新/关闭和主程序可切回。
预期结果：用户手势安全链接在系统浏览器打开，Electron 不新建窗口/标签；主程序保持可操作；危险协议和认证窗口仍被拒绝；失败有中文提示。
失败条件：仍一律拦截安全外链、在 Electron 内新建 WebContents、认证窗口被放开、主程序被阻塞，或失败时静默无反馈。
