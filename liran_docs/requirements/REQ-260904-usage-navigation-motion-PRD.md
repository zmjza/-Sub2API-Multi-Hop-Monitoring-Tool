## 1. 产品/功能概述

本任务优化现有中转站监控桌面的使用记录数据可信度、嵌入网页切换效率和全站交互质感，不新增独立 UI 壳，不改变产品信息架构。

## 2. 背景与问题

OpenCodex 日志中的输入 Token 含缓存命中量，现有页面把原始输入直接展示，导致真实输入和统计口径偏大；缓存写入未展示；日期“今天”是滚动 24 小时而不是自然日。OpenCodex 数据量上限偏小。Sub2API 服务器切换存在等待感，Radar 和常用网站没有同类快速切换入口。现有页面已有基础交互，但不同页面的状态反馈、过渡时序和动效风格不一致。

## 3. 用户与使用场景

目标用户是管理多个中转站和本机 OpenCodex 日志的开发者。主要场景包括：查看当天或自然日范围内的请求记录、核对缓存命中和性能、在多个嵌入网页之间快速切换、在桌面和窄窗口下使用全部业务页面。用户不需要新建原型或 UI 壳，只需要在现有页面上完成可感知、可访问、可验证的优化。

## 4. 产品目标

1. OpenCodex 展示和统计与真实日志字段一致，样例记录真实输入为 3,003。
2. OpenCodex 支持缓存率列、4000 条加载上限和本地自然日筛选。
3. 总览只移除渠道推荐展示，不影响倍率和渠道基础能力。
4. Sub2API 服务器、Radar、常用网站均具备即时反馈的模块内快速切换。
5. 全部主页面拥有统一、克制、高级感的交互动画，并支持减少动态效果。

## 5. 非目标与明确不做

- 不修改 OpenCodex 服务端或 `/api/logs` 协议。
- 不新增云同步、遥测、账号体系或动画依赖。
- 不删除每站倍率查看、充值比例、渠道状态、手动渠道关联或内部倍率候选/评分。
- 不新增 UI 壳、Stitch 页面、外部视觉路线或独立 Design QA 流程。
- 不复制截图中的 Sub2API 后台菜单。
- 不改变数据库 schema、认证权限、Cookie/Token 隔离和嵌入网页安全策略。
- 不新增 OpenCodex CSV 导出能力。

## 6. 当前项目事实

- 技术栈与运行环境：Electron 43、React 19、TypeScript 5.9、Vite 8、Node SQLite、Vitest 4、Playwright Electron。
- 相关模块与入口：使用记录、总览、Sub2API 服务器、Radar、常用网站及 `src/renderer/App.tsx` 顶部工具栏。
- 已有行为与限制：OpenCodex 固定 2000 条和滚动 24 小时；Sub2API 有服务器切换栏但切换反馈延迟；Radar/常用网站没有同类切换栏。
- 依赖、调用方与兼容约束：缓存率应复用 `cache-rate.ts`；嵌入网页通过主进程服务和 IPC；Renderer 不直接读取管理员令牌。

## 7. 用户流程

用户进入使用记录并切换 OpenCodex 模式，系统加载最多 4000 条日志；用户选择今天、近 7 天、近 30 天或自定义范围，页面按本地自然日筛选并更新统计和列表；用户查看 Token 明细、缓存率、首字、耗时和 t/s。用户进入 Sub2API 服务器、Radar 或常用网站后，在顶部胶囊栏点击目标条目，界面立即反馈选中/加载状态，目标网页加载成功后显示，失败时恢复原页面或提供重试。用户在任一主页面执行导航、刷新、筛选、打开弹层或提交表单时获得统一过渡反馈；启用减少动态效果时核心操作和状态仍可用。

### REQ-002 [v1.0] 修正 OpenCodex Token 字段

触发条件：OpenCodex 日志归一化或展示。
前置条件：日志包含 `usage` 或部分字段。
用户操作：查看 Token 单元格和统计卡。

数据变化：只改变 Renderer 归一化和统计口径，不回写 OpenCodex 服务。

禁止行为：不得把缓存读取重复加进真实输入或伪造缓存写入值。

### REQ-003 [v1.0] OpenCodex 缓存率、性能和日期筛选

触发条件：用户打开或筛选 OpenCodex 使用记录。
前置条件：OpenCodex 模式可读取本机日志。
用户操作：切换时间范围、查看缓存率、刷新记录。
系统行为：请求上限为 4000；Token 右侧新增缓存率列；耗时使用 `durationMs`，首字使用 `firstOutputMs`，t/s 优先使用 `displayMetrics.tokPerSecond.value`；今天为本地当天 00:00 到当前时间，近 7 天/近 30 天为含今天的自然日，自定义结束日含 23:59:59.999。
数据变化：仅更新 Renderer 读取参数、归一化字段和筛选状态。
状态变化：加载、错误、空结果和数量不足状态保持可辨识。
正常结果：缓存率按缓存读取 /（真实输入 + 缓存读取 + 缓存写入）×100 计算，复用中转站颜色边界。
异常处理：分母为 0 显示占位符；反向日期范围显示明确错误或空态。
禁止行为：不得把今天实现为最近 24 小时，不得把请求上限当成实际返回数量。
对应 AC：AC-003

## 9. 数据、状态与业务规则

- OpenCodex 字段来源为本机 `/api/logs`；真实输入、缓存读取、缓存写入、输出和总数必须分开保存。
- 缓存率分母为真实输入 + 缓存读取 + 缓存写入；分母为 0 使用占位符。
- 今天、近 7 天、近 30 天使用本地自然日；近 7/30 天均包含今天。
- 三类嵌入模块各自维护条目和持久化分区，不共享登录态。
- 动效必须尊重 reduced-motion；状态文本和焦点不能依赖动画才能理解。

## 10. 页面与 UI 需求

- OpenCodex 表格列顺序：Token 后紧跟缓存率，再显示首字、耗时 / t/s 和实际消费。
- Sub2API、Radar、常用网站嵌入工具栏顶部均有横向胶囊切换栏。
- 所有主页面保留现有信息架构，增加统一的 hover、press、focus-visible、loading、modal、success、error、selected 和 reduced-motion 反馈。
- 桌面、窄窗口和 380×260 悬浮窗均不得出现文字、按钮、表格或切换栏重叠和溢出。

## 11. 异常、边界与安全规则

- 缺失或非法日志字段显示占位符，不猜测、不伪造。
- `cacheRead > inputTokens` 时真实输入归零。
- 服务端返回少于 4000 条时显示真实数量。
- 自定义日期为空、反向或跨时区时必须有确定性行为和测试。
- 快速切换失败不得清空原页面，旧视图恢复失败时才进入错误态。
- 不输出管理员令牌、Cookie、完整 API Key、私有页面内容或敏感日志。

## 12. 兼容性与限制

- macOS ARM64 为主要真机验收平台；Windows 只做 x64 交叉构建和结构检查。
- OpenCodex 服务未启动、令牌缺失或接口异常时，页面保留现有错误态。
- 动画使用 CSS/React 原生能力，不增加运行时依赖。
- 旧的倍率、渠道、服务器、Radar 和常用网站数据必须兼容。

## 13. 影响范围

- 受影响模块：M01、M02、M08、M09、M10、M11、M16，以及 Sub2API 服务器、Radar、常用网站页面。
- 受影响文件或接口：`src/renderer/shells/usage/*`、`src/renderer/shells/overview/*`、`src/renderer/shells/sub2api-servers/*`、`src/renderer/shells/radar/*`、`src/renderer/shells/favorite-websites/*`、`src/renderer/App.tsx`、相关 CSS/测试和必要的状态接线；OpenCodex `/api/logs` 仅调整请求上限，不改协议。
- 受影响数据与状态：OpenCodex 行归一化字段、日期筛选状态、嵌入视图 active/loading/error 状态和动效状态。
- 受影响页面与 UI：全部站点、API 密钥、使用记录、渠道状态、站点管理、Sub2API 服务器、Radar、常用网站、通知、设置。
- 不受影响范围：数据库 schema、凭据和 Token 存储、远程 API 写操作、认证安全策略、倍率基础能力、Windows 真机结论。

### 禁止修改范围

禁止修改 OpenCodex 服务端、数据库迁移、认证权限、支付、Cookie/Token 导出、嵌入网页安全开关、无关功能文件和用户未提出的远程后台菜单。禁止新增动画依赖、UI 壳或独立原型文件。
