# REQ-260913 站点连通性、使用统计与渠道状态兼容 PRD

文档状态：正式 PRD
需求状态：已确认
PRD 版本：1.0
任务 ID：REQ-260913-connectivity-test
创建日期：2026-09-13

## 1. 产品目标

在“全部站点”总览中为每个站点增加普通文本“测试连通性”，允许用户选择具体 API Key 和模型，执行一次真实请求并查看流式结果。同时优化中转站/OpenCodex 使用记录统计，并兼容旧版渠道状态接口与 Sub2API channel-monitor-v2 新版矩阵接口。

本任务不实现图片、音频、视频、生图、语音、搜索或实时测试，不创建新版渠道状态专用 UI。

## 2. 需求范围与验收标准

### REQ-01 站点卡片入口

- 在每个站点卡片底部“查看渠道状态”右侧增加“测试连通性”。
- 保留充值比例、查看倍率和查看渠道状态。
- 操作区沿用现有固定槽位布局，宽屏和窄窗口不能产生异常换行、溢出或卡片高度漂移。

### REQ-02 连通性测试弹窗

- 弹窗沿用当前项目弹层规范，交互参考 sub2api 的“测试账号连接”。
- 显示站点名称、站点状态、Key 选择、模型选择、提示词输入、深色流式输出区及关闭/开始测试按钮。
- 默认提示词为 hi。
- 自动选中第一个可用模型，允许手动切换；无可用模型时禁止开始测试。
- 同一时间只允许一个活动测试；请求中禁止重复提交。
- 支持成功、失败、取消、超时和重试终态；关闭、切换站点或卸载组件时取消请求，并阻止迟到事件回写。
- 明确提示测试会产生一次真实请求并可能计入所选 Key 用量。
- 测试结果只保留在当前弹窗会话，不写入站点卡片或持久化存储。

### REQ-03 Key 与安全边界

- 只显示当前站点 active Key；默认选中当前站点当前生效 Key，没有手动选择时使用现有自动选择结果。
- Renderer 只传 siteId、keyId、模型和提示词。
- 主进程重新校验站点、Key 状态和输入边界后读取真实 Key。
- 完整 API Key 不进入 Renderer 状态、IPC 返回、日志、截图、测试夹具或持久化文件；界面只显示脱敏标签。
- 处理未登录、Key 不存在/停用、401、403、429、超时、模型不存在和上游连接失败。

### REQ-04 普通文本测试请求

- 测试请求由主进程代理，按站点实际协议选择兼容端点；Renderer 不绑定单一协议。
- 请求必须使用用户选择的 Key，不能静默回退默认 Key。
- 输出至少包含开始测试、脱敏 Key、模型、连接状态、响应文本、耗时或错误原因。
- 暂不支持媒体和其他测试模式。

### REQ-05 使用记录平均统计

- 中转站和 OpenCodex 模式均按当前筛选结果时间倒序取最近 100 条记录。
- 平均耗时：从这 100 条中筛选有效 durationMs，做算术平均。
- 平均缓存率：复用每条记录现有缓存率计算，筛选有效缓存率后做算术平均；不改为汇总 Token 后重新计算。
- 有效样本不足 100 条时按实际样本数计算，并显示样本数或等价提示；无有效样本显示占位符。
- 数据加载层必须覆盖足够记录，不能只对当前 20 条分页求平均。
- 新增“平均缓存率”卡片；缩窄总请求数、总消费、平均耗时卡片以容纳四卡片同排布局。
- 筛选、站点切换、模式切换和刷新后重新计算统计。

### REQ-06 双版本渠道状态适配

- 每个站点先探测新版 GET /api/v1/channel-monitor-v2/matrix，固定请求 range=90m、group_by=platform_group 和站点时区。
- 只有明确不存在、未启用、V2 模式未开启、404/405 或响应契约不合法时才回退旧版接口。
- 429、5xx、超时和网络抖动属于临时失败：保留旧缓存和错误状态，下个周期重新探测 V2，不永久标记为旧版。
- 401/403 显示鉴权或权限问题，不能伪装为旧版成功。
- V2 成功后同一站点后续刷新优先 V2；能力状态只作为内存优化，重启或失效后重新探测。
- V2 与旧版响应均在主进程归一化为现有渠道列表、详情、状态、时间线、指标和覆盖时间模型。
- V2 读取 data.items[]、metrics、health、buckets 和 coverage，至少提取请求数、成功率、错误率、缓存率、TTFT/duration、健康等级、评分、时间桶和覆盖时间。
- V2 健康等级映射为现有 UI 语义：healthy→normal、warning→degraded、critical→failed、unknown→unknown；无请求量优先显示未知/待核验。
- coverage.data_through 是数据有效上界；未来 bucket、超过上界的记录、未覆盖 bootstrap 区间不得成为最新状态。
- coverage_complete=false 或 bootstrap.active=true 时保留可显示数据并标记待核验/部分覆盖。
- platform 与 group_id/group_name 只能通过现有严格分组关系关联；歧义时显示未知，不借用其他分组或数组第一项。
- 不改动当前渠道状态页面、卡片、弹窗和悬浮窗视觉结构与交互；新版只替换归一化参数。

## 3. 非功能要求

- 复用现有站点级单飞、并发上限、revision、防旧响应回写、stale-while-revalidate 和退避机制。
- 输入、响应和错误在边界处校验；错误需结构化并脱敏。
- V1/V2 混用时单站失败不得阻塞其他站点。
- 所有新增状态和字段必须保持现有浅色 UI、键盘可用性和窄窗口可读性。

## 4. 影响模块

- 总览卡片与弹窗：src/renderer/shells/overview/OverviewPage.tsx、新增或复用总览弹窗组件及局部 CSS。
- 使用记录：src/renderer/shells/usage/UsagePage.tsx、OpenCodexUsagePage.tsx、opencodex-data.ts、usage.css。
- 主进程适配和服务：electron/main/adapters/sub2api-adapter.ts、electron/main/services/site-service.ts。
- IPC 与契约：electron/main/index.ts、electron/preload/bridge.cts、electron/preload/index.ts、electron/shared/contracts.ts。
- 现有渠道缓存和弹窗：rate-channel-status-loader.ts、ChannelStatusPopover.tsx 及相关测试。

## 5. 验收矩阵

- 统计覆盖 0、1、20、99、100、超过 100 条，缺失 duration/cache、筛选切换和窄窗口四卡片布局。
- V2 覆盖合法响应、空 items、无请求、部分 coverage、bootstrap、未来 bucket、四种健康等级、404/405、401/403、429、5xx、超时和非法 JSON。
- V1 回归渠道列表、详情、时间线、缓存、手动关联、重试和悬浮窗。
- 混用站点覆盖 V2 成功持续刷新、明确不支持回退和临时失败重探测。
- 连通性覆盖 Key 切换、模型默认/手动选择、流式输出、取消、重试、错误脱敏和真实用量提示。
- 安全验证完整 API Key 不进入 Renderer、IPC 返回、日志、截图、测试夹具或持久化文件。

## 6. 明确不在本 PRD 内

- 图片、音频、视频、生图、语音、搜索和实时测试。
- 新版渠道状态专用视觉页面、时间窗口选择控件。
- 测试结果持久化到站点卡片。
- 独立管理员 V2 会话；默认使用已登录用户可访问的用户接口。
