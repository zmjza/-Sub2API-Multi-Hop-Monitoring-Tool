## 1. 产品/功能概述

修复 API 密钥页高度与分组下拉裁切，新增应用内嵌的禾维 AI 智商检测中心，并缩小悬浮窗今日统计数字。禾维入口列出全部已保存中转站及各站在“全部站点”中当前选定的 API Key；用户每次主动选择检测站点，应用自动填入接口地址与 Key，但不自动发起检测。

## 2. 背景与问题

- API 密钥表格当前随 Key 行数收缩，Key 较少时右侧区域没有延伸到窗口底部。
- 分组下拉处于可滚动表格和固定高度单元格内，会被祖先 overflow 裁切，末行和多 Key 场景明显。
- 禾维 AI 每次需要手动填写 API 接口地址和 API Key，重复操作耗时。
- 用户保存多个站点，检测前必须明确选择本次站点，不能默认或自动猜测。
- 悬浮窗“今日 Token”“今日消费”当前数值为 24px，视觉比例偏大。

## 3. 用户与使用场景

- 用户在 API 密钥页查看少量或大量 Key，表格面板始终延伸至主窗口底部。
- 用户打开首行、中间行或末行的分组下拉，菜单完整显示并可键盘操作。
- 用户点击“智商检测中心”，从全部已保存站点中主动选择本次检测站点。
- 用户进入应用内嵌禾维页面后，接口地址和对应 Key 已填好，只需自行点击检测。
- 用户查看或双击悬浮窗今日统计时，数字更紧凑，导航行为保持不变。

## 4. 产品目标

1. API 密钥内容区稳定填满主窗口剩余高度，不由 Key 数量决定高度。
2. 分组下拉不被表格、行或视口裁切。
3. 禾维检测前必须手动选择站点，不设置默认站点。
4. 自动填充所选站点的模型接口地址（baseUrl/v1）和当前 Key，不自动提交检测。
5. 完整 API Key 不进入 URL、日志、文档、通知、截图或新增持久化配置。
6. 悬浮窗数字缩小后仍清晰、单行且不影响双击导航。

## 5. 非目标与明确不做

- 不自动点击禾维 AI“开始检测”。
- 不保存禾维专用默认站点、默认 Key 或检测历史。
- 不登录禾维账号，不绕过验证码、风控、登录或付费限制。
- 不改 API Key 后端结构、远程分组协议、统计口径或 Key 选择规则。
- 不为下拉框或内嵌页引入新依赖。
- 不重做悬浮窗整体布局。
- 不向禾维以外的第三方网站开放自动填充。

## 6. 当前项目事实

- API 密钥页由 ApiKeysPage 和 api-keys.css 实现，右侧面板为 flex 布局，表格容器具有 overflow:auto。
- 分组控件为自定义 GroupSelect，菜单当前绝对定位在表格单元格内，固定 max-height 为 320px。
- 全部站点已维护每个站点的当前 Key 选择，并已有站点弹层、App 状态和主进程 IPC 接线。
- 项目已有 WebContentsView 内嵌网页、固定 origin、安全导航和外部窗口拦截模式，可复用而无需新增浏览器依赖。
- 悬浮窗固定尺寸，今日数值样式位于 floating.css，当前 font-size 为 24px。
- API Key 属于敏感数据，现有 preload、IPC、日志脱敏和窗口安全边界必须继续保留。

## 7. 用户流程

用户打开 API 密钥页 → 页面填满剩余高度 → 用户打开任意分组下拉 → 菜单按视口上下空间定位并完成选择。

用户在全部站点点击“智商检测中心” → 站点选择弹层列出全部已保存站点和当前 Key 摘要 → 初始无选中项 → 用户主动点击一个可检测站点 → 主窗口打开受控禾维 WebContentsView → 页面加载完成后自动填入接口地址和完整 Key → 应用提示填充成功 → 用户自行点击禾维检测按钮 → 用户可刷新、重新选站、返回或关闭。

## 8. 功能需求

### REQ-01 API 密钥页面填满剩余高度

触发条件：进入 API 密钥页、切换站点、数据状态变化或调整主窗口尺寸。
前置条件：API 密钥页已挂载，主窗口存在可计算的内容高度。
用户操作：查看、筛选、刷新、分页或调整窗口尺寸。
系统行为：页面主体、右侧面板和表格滚动区共同占用主窗口剩余高度；左侧渠道区独立滚动；工具栏、反馈区、表头和分页保持原位。
数据变化：不改变 Key、分组、筛选或分页数据，只改变布局尺寸和滚动容器。
状态变化：loading、success、empty、error、unsupported、auth-required、refreshing、partial 均使用稳定剩余高度。
正常结果：一行 Key 时表格外框仍延伸到页面底部；多行 Key 时仅表格内部滚动。
异常处理：720px 最小窗口或内容超宽时保留内部滚动，不产生页面级不可控溢出。
禁止行为：禁止按 Key 行数收缩主面板；禁止用整页固定像素高度掩盖问题。
对应 AC：AC-01

### REQ-02 API 密钥分组下拉完整显示

触发条件：用户点击或键盘打开任意 Key 行的分组下拉。
前置条件：当前行存在至少一个分组选项，且不处于远程写入禁用状态。
用户操作：点击触发器，使用鼠标或上下方向键浏览，Enter 选择，Escape 或点击外部关闭。
系统行为：浮层脱离会裁切它的表格祖先，按触发器实时视口坐标定位；下方空间足够时向下展开，否则向上展开；菜单高度按可用空间限制并内部滚动。
数据变化：选择新分组后继续调用现有远程分组切换链路；仅布局定位不修改数据。
状态变化：closed、open-below、open-above、selecting、writing、success、rollback。
正常结果：首行、中间行、末行和多 Key 场景均能看到并选择全部选项。
异常处理：表格滚动、窗口滚动、缩放、触发器卸载或站点切换时关闭或重新定位；写入失败沿用现有回滚和错误反馈。
禁止行为：禁止仅提高 z-index；禁止取消表格滚动；禁止改变平台、倍率、分组名称和远程写入语义。
对应 AC：AC-02

### REQ-03 智商检测中心站点选择

触发条件：用户在全部站点页面点击“智商检测中心”。
前置条件：主窗口可读取已保存站点列表及各站在“全部站点”中的当前 Key 选择。
用户操作：查看站点和脱敏 Key 摘要，主动点击本次要检测的站点，或关闭弹层。
系统行为：列出所有已保存站点；每项显示站点名称、安全地址摘要、当前 Key 名称和脱敏 Key；初始不预选任何站点。
数据变化：选择只创建本次检测上下文，不修改全部站点的当前站点、当前 Key、排序或持久化设置。
状态变化：closed、selecting、opening、unavailable。
正常结果：只有用户明确点击的可检测站点进入禾维页面。
异常处理：无当前 Key、Key 不可用、地址无效或站点已删除时显示原因并禁用继续；无站点时显示空态。
禁止行为：禁止默认选择第一项、当前站点、最近站点或任意 Key；禁止在弹层展示完整 Key。
对应 AC：AC-03

### REQ-04 应用内嵌禾维 AI 并自动填充

触发条件：用户在站点选择弹层中点击一个可检测站点。
前置条件：所选站点仍存在，当前 Key 可用，接口地址可规范化，主窗口允许创建受控网页视图。
用户操作：等待页面加载，核对自动填充结果，自行点击禾维检测按钮；也可刷新、重新选站、返回或关闭。
系统行为：打开固定禾维 HTTPS 页面；主进程读取规范化接口地址和完整 Key；页面加载后识别 API 接口地址和 API KEY 输入框，写入值并触发 input/change；验证字段值后报告成功。
数据变化：只创建会话级临时填充上下文；不修改站点、Key、禾维页面设置或本地持久化数据。
状态变化：opening、loading、filling、filled、fill-error、load-error、closed。
正常结果：用户进入禾维页时两个字段已正确填入，但检测尚未发起。
异常处理：页面加载失败可重试；字段找不到、值未生效、站点或 Key 失效时报告自动填充失败并允许重新选择；非允许导航被阻止。
禁止行为：禁止自动提交检测；禁止把完整 Key 写入 URL、日志、通知、错误文本、localStorage、文档或截图；禁止向远程页面暴露 Node、Electron、文件系统、数据库或任意 IPC。
对应 AC：AC-04

### REQ-05 悬浮窗今日统计数字缩小

触发条件：悬浮窗渲染今日 Token 和今日消费。
前置条件：悬浮窗已取得当前站点统计或占位状态。
用户操作：查看数字，双击指标进入使用记录，或通过键盘操作指标按钮。
系统行为：将当前 24px 数值缩小，以 20px 为首选；真实视觉验证允许在 20–22px 内微调，保持两列等宽、单行和原有间距关系。
数据变化：不改变 Token、消费、格式化结果、站点或 Key 上下文。
状态变化：loading、success、stale、error 的显示逻辑保持不变。
正常结果：数字视觉比例更协调，大数值不溢出或遮挡底部栏。
异常处理：极长数值仍使用现有紧凑格式；若 20px 影响可读性，可在限定范围内调整并记录视觉证据。
禁止行为：禁止改变双击导航、统计口径、悬浮窗尺寸或底部状态栏。
对应 AC：AC-05

### REQ-06 使用记录全部 API Key 筛选稳定显示

触发条件：用户在使用记录页面将 API Key 筛选切换为“全部”。
前置条件：当前站点存在一个或多个 API Key，或当前站点没有可用 Key。
用户操作：选择“全部”、切换时间范围、切站、快速切换到具体 Key 再切回全部、刷新或重试。
系统行为：清理具体 Key 筛选值，以无 api_key_id 的查询请求当前站点全部记录；列表和统计使用同一代查询结果，旧 Key 请求迟到时丢弃。
数据变化：不修改站点、Key、偏好或远端数据。
状态变化：loading、success、empty、error、refreshing 保持与具体 Key 筛选一致。
正常结果：选择“全部”时显示当前站点全部 API Key 的记录；确实无记录时显示空态；统计与列表范围一致。
异常处理：查询失败保留错误态并可重试；快速切换或切站不会用旧 Key 结果覆盖全部结果。
禁止行为：禁止把空值序列化成无效 Key；禁止隐式沿用旧 Key；禁止为修复而默认选择某个 Key。
对应 AC：AC-07

## 9. 数据、状态与业务规则

- 站点集合来自现有已保存站点列表。
- 每站检测 Key 固定使用其在“全部站点”页面当前选定的 API Key；本任务不引入第二套 Key 选择或默认值。
- 站点选择弹层初始选中值必须为空。
- 完整 Key 仅在本次受控自动填充所需的最短生命周期内存在；关闭、刷新、重选、导航离开或窗口销毁时清理上下文。
- 网页视图状态为 opening、loading、filling、filled、fill-error、load-error、closed。
- “填充成功”必须同时满足两个目标输入框存在、写入后读取值相符、必要事件已派发；不能只以 executeJavaScript 无异常作为成功。
- 禾维页面只自动填充，不自动检测。

## 10. 页面与 UI 需求

- “智商检测中心”入口位于全部站点主页面的现有导航/操作体系内，沿用当前紫色主题、按钮反馈和响应式规则。
- 站点选择弹层显示标题、说明、站点列表、Key 名称、脱敏 Key、不可用原因和关闭操作；不展示完整 Key。
- 站点列表不预选；可检测项有清晰 hover、focus 和 pressed 状态；不可检测项可读但禁用。
- 内嵌页沿用现有 WebContentsView 工具栏结构，至少提供返回全部站点、重新选择、刷新和关闭。
- 内嵌页面 loading、filled、fill-error、load-error 状态必须有应用层可见反馈。
- API 密钥面板底边与页面内容底部对齐；左右区域独立滚动。
- 下拉菜单使用现有视觉样式，改变定位和方向时不得闪跳或遮住触发器。
- 悬浮窗只调整两项数值字号，不重排标题、余额、近期可用率或底部栏。

## 11. 异常、边界与安全规则

- 只允许固定 HTTPS 禾维官方域名及经确认的同站跳转；拒绝 http、file、javascript、data、凭据 URL 和未知 origin。
- 禾维页面发起新窗口、下载、权限请求或未知导航时按现有安全策略拒绝或安全外开，不能获得主应用能力。
- 远程网页不得使用应用 preload，不得访问 Node、Electron、文件系统、数据库或任意业务 IPC。
- API Key 不得出现在 URL、日志、通知、错误消息、测试标题、截图文件名、文档或新增配置中。
- 禾维 DOM 变化时安全失败并提示重试，不使用坐标点击或自动提交绕过字段识别。
- 站点、Key 在会话中删除或切换时终止本次填充，要求重新选择。
- 分组下拉定位不得造成焦点丢失、错误行写入或旧菜单残留。
- 页面高度调整不得破坏空态、分页、窄窗口和左侧渠道滚动。

## 12. 兼容性与限制

- 支持项目现有 macOS ARM64 与 Windows x64 构建目标。
- macOS 必须完成真实应用内嵌、自动填充和视觉验收。
- 没有 Windows 真机时只记录交叉构建与自动化证据，不声称 Windows 真机通过。
- 禾维 AI 是外部网页，其 DOM、路由、可用性、费用和隐私规则可能变化；应用只保证当前已验证页面的安全填充和失败反馈。
- 禾维页面若新增登录、验证码或风控，用户自行处理，本任务不绕过。

## 14. 验收标准

### AC-01 页面高度

对应需求：REQ-01
验收步骤：分别构造 1 个 Key、多个 Key、空态和错误态，在宽窗口与 720px 最小窗口查看页面高度和滚动容器。
预期结果：面板向下填满剩余高度；Key 多时表格内部滚动；左侧独立滚动；页面无底部大片空白或不可控溢出。
失败条件：面板仍随行数收缩、页面整体出现错误滚动、底部空白明显或状态页高度跳变。

### AC-02 分组下拉

对应需求：REQ-02
验收步骤：依次打开首行、中间行、末行和长选项菜单；滚动表格、缩放窗口，并使用方向键、Enter、Escape 和点击外部。
预期结果：菜单按空间向上或向下展开，选项完整可访问，定位跟随正确行，选择沿用现有写入和回滚。
失败条件：菜单被裁切、漂移、打开错误行、无法键盘选择、滚动后残留或写入语义回归。

### AC-03 站点选择

对应需求：REQ-03
验收步骤：准备多个已保存站点，包含可用 Key、无 Key、无效地址和已失效 Key；点击智商检测中心。
预期结果：列出全部站点和脱敏 Key 摘要，初始无选中项，仅主动点击的可用站点继续，不可用项显示原因。
失败条件：存在默认站点、展示完整 Key、不可用站点仍可继续、选择改变全部站点当前状态。

### AC-04 禾维自动填充与安全

对应需求：REQ-04
验收步骤：选择可用站点打开真实禾维页面；检查两个字段、应用反馈、网络导航、刷新/重选/关闭；模拟字段缺失和非允许跳转；检查日志和持久化文件。
预期结果：接口地址和完整 Key 正确填入但未自动检测；失败明确可恢复；远程页无应用能力；Key 不出现在 URL、日志、通知、文档、截图和持久化数据。
失败条件：字段为空或错误却报告成功、自动发起检测、Key 泄漏、未知 origin 可导航、远程页获得 Node/Electron/IPC 能力。

### AC-05 悬浮窗字号与回归

对应需求：REQ-05
验收步骤：在正常值、大 Token、高消费、loading 和 error 状态查看悬浮窗，并测试双击和键盘进入使用记录。
预期结果：数值比当前 24px 更小且清晰、单行、无重叠；双击导航、统计和底部栏不变。
失败条件：字号未变化、过小难读、数值溢出、布局抖动或导航行为回归。

### AC-06 综合回归与发布

对应需求：REQ-01、REQ-02、REQ-03、REQ-04、REQ-05
验收步骤：执行格式、lint、typecheck、Vitest、生产构建、Electron E2E、macOS 真机、macOS DMG、Windows NSIS、完整 diff 和统一发布流程。
预期结果：相关检查通过，版本与 CHANGELOG 一致，双平台资产来自同一提交和版本，两个远端及 GitHub Release 验证成功。
失败条件：任一必需检查失败、Windows 交叉构建冒充真机、旧资产复用、版本/说明/SHA 不一致或未验证 Release 资产。

### AC-07 使用记录全部 API Key

对应需求：REQ-06
验收步骤：在有多把 Key 的站点分别选择具体 Key、全部、切换时间范围、切站并快速重复切换，检查列表、分页、统计、空态和失败重试。
预期结果：全部筛选发送不带 api_key_id 的查询并显示全站记录；旧具体 Key 请求不会覆盖全部结果；空结果与真实无记录一致。
失败条件：全部筛选无记录而具体 Key 有记录、请求仍携带旧 Key、统计和列表范围不一致或切换后显示旧结果。
