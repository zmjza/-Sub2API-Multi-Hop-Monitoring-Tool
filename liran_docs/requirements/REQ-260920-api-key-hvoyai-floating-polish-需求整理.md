## 用户原始目标

用户要求修复和优化三个功能：

1. API 密钥页面的分组下拉框在截图所示红框区域打开后看不到完整选项，多 API 密钥时也存在同样问题。用户判断当前页面可能根据 API 列表控制高度，要求把高度直接设置到页面底部，并修复密钥分组下拉框显示。
2. 在全部站点页面新增“智商检测中心”入口，使用禾维 AI（https://www.hvoyai.com/）进行检测。当前每次检测都要手动填写 API 接口地址和 API Key，用户要求自动填写，之后只需点击测试；可以使用内联浏览器，也可以采用更好的实现方式。
3. 悬浮窗中“今日 Token”和“今日消费”下面的数字字号过大，要求适当缩小。

## 已确认需求

### REQ-01 API 密钥页面高度和分组下拉框

- API 密钥列表区域应尽量填满当前窗口剩余可用高度，避免因 API 密钥数量、左侧渠道卡片数量或容器高度计算导致右侧表格区域出现不必要的空白或被压缩。
- 分组下拉框打开后，选项必须完整可见或可滚动访问，不能被表格容器、表格行或页面边界裁切。
- 多 API 密钥场景下，每一行的分组下拉框都必须保持独立定位、可打开、可选中。
- 保留当前分组、平台和有效倍率展示；修复只涉及布局、裁切、层级和滚动行为时，不改变远程分组切换业务语义。
- 需要覆盖宽窗口、窄窗口、单 Key、多 Key、选项较多和最后一行打开下拉框等场景。

### REQ-02 禾维 AI 自动填充检测

- 在全部站点页面增加“智商检测中心”入口，入口位置和交互应符合现有站点卡片/菜单风格。
- 点击入口后先打开站点选择器，列出所有已保存的中转站，以及各站在“全部站点”页面当前选定的 API Key 信息。
- 不预选、不默认任何站点；用户必须主动点击本次要检测的中转站。
- 选定站点后，使用该站在“全部站点”页面当前选定的 API Key；若该站没有可用或已选 Key，应在选择器中明确标记并阻止继续检测。
- 打开禾维 AI 检测页后，所选站点的 API 接口地址和对应 API Key 应自动带入，用户直接点击检测即可。
- 自动填充不能把完整 API Key 写入日志、文档、URL、持久化配置或测试截图。
- 当当前站点、当前 Key 或接口地址不可用时，需要显示明确的可恢复错误，不得静默打开一个看似可用但字段为空的页面。
- 打开检测页后主应用仍应保持可操作；检测页可使用现有安全的外部浏览器/内联网页容器能力，最终实现路线待确认。
- 需要验证 API 地址拼接、Key 传递、页面打开、字段填充失败和用户取消/关闭等状态。

### REQ-03 悬浮窗统计数字字号

- 适当缩小悬浮窗“今日 Token”和“今日消费”数值字号，使其与标签、卡片宽度和其他统计内容保持比例。
- 不改变数值格式、统计口径、点击进入使用记录的现有行为和底部状态栏布局。
- 需要在宽窗口、窄窗口和大数值显示场景确认不溢出、不换行、不遮挡。

## 当前代码事实

- API 密钥页入口：src/renderer/shells/api-keys/ApiKeysPage.tsx。
- API 密钥页样式：src/renderer/shells/api-keys/api-keys.css。
- 分组下拉为自定义 GroupSelect，当前菜单存在固定 max-height 和表格容器裁切风险，需要沿完整 DOM/定位链路修复。
- 全部站点页面入口：src/renderer/shells/overview/OverviewPage.tsx。
- 悬浮窗入口：src/renderer/shells/floating/FloatingWindow.tsx，样式在 src/renderer/shells/floating/floating.css。
- 现有系统浏览器/外部网页打开能力经过主进程和 preload 约束，已有站点充值页打开链路，可作为禾维入口的安全复用候选。
- 现有站点和 Key 数据均由主进程/受控 IPC 提供，不能从 Renderer 任意读取完整凭据或绕过现有安全边界。

## 已确认实现口径

1. 禾维 AI 检测页使用应用内嵌浏览器。入口先展示全部已保存中转站及各站在“全部站点”中当前选定的 API Key；不预选站点，用户主动选择后才进入检测页并自动填充。
2. API 密钥页右侧表格面板始终向下填满主窗口剩余高度，不再按 API Key 数量收缩；左侧渠道区独立滚动；分组下拉根据视口空间向上或向下展开，并在必要时内部滚动。

## 本轮新增需求

### REQ-04 使用记录“全部 API Key”筛选修复

- 使用记录页面选择 API Key“全部”时，必须查询并显示当前站点全部 API Key 的使用记录。
- 不得因为空值、旧的具体 Key 筛选或异步请求顺序，导致只有选择具体 API Key 才有记录。
- 切换到“全部”时应清理旧 Key 筛选，重新加载列表与统计；后续切换具体 Key 仍保持原有筛选语义。
- 空结果必须真实表示全部 Key 在所选时间范围内无记录，不能用某一个 Key 的结果冒充全部。
- 覆盖今天、近 7 天、近 30 天和自定义时间范围，以及切站、快速切换筛选和失败重试。

## 暂不纳入范围

- 不改 API Key 后端数据结构、分组接口和远程切换协议。
- 不把 API Key 写入禾维 URL 查询参数、应用日志、需求文档或发布说明。
- 不新增独立 UI 壳或引入新的浏览器依赖，优先复用现有 Electron、preload 和外部网页打开能力。
- 不改变悬浮窗统计口径和既有导航行为。
