## 用户已提出的需求

### REQ-1 悬浮窗近期可用率记录数量

- 所有渠道状态可视化入口统一固定显示最近 18 格：渠道状态主页面、全部站点渠道状态弹层、API 密钥左侧渠道区和悬浮窗近期可用率条。
- 当前记录超过 18 格时只保留最新 18 次；不足 18 次时从左侧补灰色空槽，真实记录靠右，不能伪造成功记录。
- 该规则只作用于渠道状态时间线，不改变使用记录图表或其他非渠道状态数据。

### REQ-2 渠道状态时间线与 V2 指标布局

- V1 渠道状态卡片下方的记录格固定只显示最近 18 次。
- V2 渠道状态卡片下方的记录格固定只显示最近 18 次。
- 记录格颜色语义保持现有颜色，不因本次美化改动状态颜色。
- V1 记录格的形状、圆角、间距、尺寸比例需要优化，让视觉更整齐、舒适、易读；具体视觉方案由 Codex 根据参考图和现有设计系统确定。
- V2 记录格同样需要使用统一且更美观的形状规则，保持与 V1 的视觉语言一致。
- V2 卡片中的“缓存率”“首 Token”“可用率”必须处于同一行；无论窗口宽度如何变化，都不能把其中一项折到下一行。
- 响应式布局不得通过隐藏指标、缩写成无法识别的文案或横向溢出来满足“一行”；需要保留三个指标的可读性。
- V2 无论选择 90m、24h、7d 还是 30d，视觉时间线都固定显示最近 18 个桶；时间窗只改变数据来源和桶间隔，不改变可视槽位数量。

### REQ-3 V1/V2 渠道按平台分类展示

- V1 与 V2 渠道状态都必须按平台/提供方分类展示，不再把所有渠道直接平铺在同一组网格中。
- 分类布局参考用户提供的图 3、图 4、图 5：每个分类有独立的分类头，包含平台图标、平台名称和该分类数量；分类内部再展示渠道卡片网格。
- V1 与 V2 使用同一套分类顺序、分组层级和卡片网格原则，但各自保留协议对应的指标内容。
- 分类名称、分类数量和卡片内渠道名称必须以运行时获取的数据为准同步展示，不能写死具体渠道清单。

### REQ-4 平台图标颜色与分类图标

- Gemini：使用浅蓝色图标。

### REQ-6 API 密钥页面重构与渠道状态联动

- API 密钥页面改为“左侧渠道状态辅助区 + 右侧 API 密钥表格”的组合布局。
- 参考当前附图的红框区域，在表格左侧预留一块浅色渠道状态区域；原有“名称、API 密钥、分组、平台、有效倍率、当前并发、消费、状态、创建时间”等表格字段整体右移。
- 表格需要重新合理分配列宽，在现有窗口尺寸变化下保持字段可读，不得发生内容溢出、布局破坏或非预期换行。
- 左侧渠道状态区域直接复用现有渠道状态数据接口、缓存和状态语义，不新增一套重复请求链路，不伪造渠道状态。
- 左侧顶部固定提供五个分类：OpenAI、Anthropic、Grok、Gemini、其他。
- 默认不提供“全部”分类，首次进入默认选中 OpenAI。
- 用户切换分类后，左侧区域只显示当前选中分类对应的渠道状态。
- 五类平台名称、图标和颜色沿用本任务 REQ-3、REQ-4 的分类规则；其他分类使用紫色图标。
- 主要使用目的：用户在 API 密钥页查看所选平台的渠道健康状况，再为 API Key 选择或切换更合适的分组。
- 已确认：切换平台分类只切换左侧渠道状态，不自动改动任何 API Key 分组；真正切换分组仍由每行现有分组下拉框触发。
- 若当前选择分类没有渠道记录，应显示明确空态，不自动回退到其他分类或全部分类。
- 当前选中的 API 密钥分类只影响左侧渠道区；右侧 Key 搜索、分组筛选、状态筛选、分页和写入动作保持原有语义。
- API 密钥左侧渠道卡默认只读；点击卡片不修改分组、不保存关系。若需要查看主渠道详情，使用明确的“查看渠道状态”入口，不能把整张卡片误当作分组操作。

### REQ-10 全部站点测试连通性状态动效

- 全部站点的站点状态卡片点击“测试连通性”后，测试账号连接弹窗中的结果/日志区域需要从当前静态文本框升级为有明确状态反馈的交互面板；保留现有深色面板和日志信息层级，不用动画替代真实结果。

- 点击开始测试时提供清晰的启动反馈（按钮按下态、面板状态切换或进度提示）；等待响应时提供持续但克制的处理中反馈（例如呼吸/扫描/逐行日志入场），让用户知道请求仍在进行。

- 测试进行中应禁用重复启动，避免并发请求、重复日志和状态竞态；关闭弹窗或取消测试后，迟到的事件不得把弹窗重新改回成功/失败态。
- 测试状态必须绑定 `started`、`delta`、`completed`、`failed`、`cancelled` 和超时失败；等待中应显示处理中而不是空白日志。成功以 `completed` 为准，失败以 `failed` 为准，取消后迟到的 `delta/completed/failed` 必须丢弃。
- 现有弹窗在运行中会把开始按钮改成取消测试；本需求保留该能力，并补齐等待、成功、失败、超时的视觉状态，不新增第二套测试接口。
- 测试会消耗所选 Key 的真实用量，动效不得弱化或隐藏该风险提示。
- 动效必须保持现有 Key 脱敏和日志安全边界，不能把完整 API Key、凭据或敏感请求内容写入视觉日志、DOM 快照或持久化数据。
- 正常动效需要明显、丝滑且不造成布局跳动；支持 `prefers-reduced-motion`，降级时保留状态颜色、图标、文案和可操作反馈。

### REQ-11 全部站点站点卡片快捷充值入口

- 全部站点的每张站点状态卡片在“测试连通性”按钮右侧新增一个快捷充值按钮；按钮与现有卡片操作保持同一视觉体系、尺寸和对齐规则，使用清晰的金额/钱包语义图标，由 Codex 选择与现有图标风格一致的具体图形，并提供中文悬停提示和无障碍名称。
- 点击快捷充值时根据当前 `siteId` 读取已保存的站点网址，不允许从卡片文案、用户输入或未经校验的 DOM 字符串拼接地址。
- 站点网址先按 URL 规则规范化，再追加单个 `/purchase` 路径段；去除末尾多余斜杠，避免出现 `//purchase` 或重复 `/purchase`。例如保存 `https://mdkj.lol` 时打开 `https://mdkj.lol/purchase`；站点自身不存在该菜单时，网站返回的 `/dashboard` 跳转视为可接受结果。
- 快捷充值目标只允许站点 origin + `/purchase`，不携带查询参数、hash、用户名、密码或站点账号凭据；已保存地址若已是 `/purchase` 则不再重复追加。
- 按钮位置固定在“测试连通性”右侧，与现有充值比例、查看倍率、查看渠道状态、测试连通性同一操作行；窄卡片时优先压缩内边距，不得把快捷充值挤到下一行或遮挡测试按钮。
- 打开容器复用现有 Chrome 可执行文件探测：macOS/Windows/Linux 优先 Google Chrome；找不到时回退系统默认浏览器。禁止为充值页启动带远程调试端口的认证 Chrome 会话。
- 仅允许 `http`/`https` 协议和无用户名、无密码的 URL；拒绝 `file:`、`javascript:`、`data:`、自定义协议、凭据 URL、无法解析的地址和明显越权的路径，并在应用内给出中文失败提示。
- 由主进程统一调用系统浏览器打开地址：优先使用本机已安装的 Google Chrome；Chrome 不可用时使用系统默认浏览器或可用的其他浏览器。不得把浏览器命令、站点 URL 或参数直接拼成可注入的 shell 字符串。
- 打开浏览器后，主程序和悬浮窗保持可用，不能把当前 Electron 页面替换成充值页，也不能改变当前站点选择、Key 分组或渠道状态缓存。浏览器启动失败、站点网址缺失或地址校验失败时必须有可感知的错误反馈和可重试入口。
- 充值按钮点击应与卡片选中、下拉框、备注和测试连通性操作隔离，不触发重复的卡片选择或其他按钮动作；快速连续点击需要去重或明确提示正在打开。

### REQ-12 Sub2API 服务器、雷达和常用网站的新页面行为

- Sub2API 服务器、雷达、常用网站中由用户主动点击触发的安全链接，允许按链接语义打开新页面/新标签，不再对所有新窗口请求一律拦截；主程序当前页面仍保持打开并可继续交互，用户可随时切回自己的应用。
- 默认按“系统浏览器新标签/新窗口”处理外部新页面：优先复用系统浏览器已有窗口创建新标签，浏览器不支持或不可用时创建新窗口；不得用新页面覆盖主程序窗口。具体入口沿用现有系统浏览器打开能力，不额外引入自定义浏览器标签管理。
- 新页面打开必须复用现有协议、域名和凭据安全策略：只允许经过校验的 `http`/`https` 地址，拒绝 `javascript:`、`file:`、`data:`、自定义协议、包含用户名/密码的 URL 和未经用户操作触发的弹窗；不得把 Cookie、Token、API Key 或其他会话凭据拼入新页面地址、日志或 IPC 载荷。
- 雷达和常用网站的当前内嵌页面仍保留返回、前进、刷新和关闭能力；允许新页面不代表放开任意导航、任意 WebContentsView 或任意外部进程创建。新页面只扩展用户明确点击的安全目标。

- 现有拦截点必须改成“校验后外开”：`electron/main/index.ts` 雷达视图、`electron/main/services/sub2api-server-manager.ts`、`electron/main/services/favorite-websites-manager.ts` 当前一律 `action: 'deny'`。用户主动点击的安全 `http/https` 目标改为系统浏览器打开并继续 deny Electron 新窗口。交互认证窗口继续全部拒绝，不纳入本需求。
