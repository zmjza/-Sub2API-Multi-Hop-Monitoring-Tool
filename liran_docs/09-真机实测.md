### 验收批次

建议使用至少两个递增 patch 测试包（例如 `1.4.6` -> `1.4.7` -> `1.4.8`），每个包的 GitHub Release 说明必须写明“真机更新测试专用、无业务变化”。测试包只用于更新链路，不得覆盖功能版本结论。

### macOS ARM64

1. 使用旧版本启动，确认版本徽标、站点配置、SQLite 数据和安全存储存在。
2. 通过启动检查、版本徽标和设置页分别触发检查，确认 single-flight、无更新和网络错误状态。
3. 发布测试 patch 后确认显示版本号、更新说明、跳过和稍后提醒。
4. 下载 DMG，确认进度、校验、文件来源和错误状态；确认当前应用仍可运行。
5. 自动打开 DMG；记录 ad-hoc、未公证条件下是否需要用户手动替换 App，禁止写成静默自动更新。
6. 替换后重新启动，确认 SQLite、站点、设置和 safeStorage 数据保留。
7. 保存截图、DMG/URL/SHA-256、系统版本、应用版本和实际操作日志；敏感信息脱敏。

### Windows x64

1. 先用交叉构建检查 NSIS、blockmap、内部版本和资源结构；此步骤不等同真机通过。
2. 在真实 Windows 环境用旧版本检查测试 patch，确认更新说明、下载、自动安装和自动重启。
3. 验证跳过版本、稍后提醒、安装失败回退、数据保留和再次检查。
4. 记录 Windows 版本、架构、安装包版本、Gitee 资源、日志和截图；没有 Windows 环境时保持“待验证”。
