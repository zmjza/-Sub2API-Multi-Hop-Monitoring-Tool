## 2026-07-12 首次原话

> 因为我有很多个中转站。我想做一个悬浮窗形式可以实时查看剩余额度，当前中转站apikey倍率，使用记录，渠道状态。同时想看其他的中转站，点击切换就能了。你帮我想想这个方案怎么实现，我们应该需要多轮对话吧需求整理好

## 2026-07-12 确认结果与变更记录

- 中转站均为 sub2api 二开站，使用普通用户账号；登录无验证码。
- 放弃以 Playwright 多开浏览器作为查询主链路，改为直接调用 HTTP API。
- 同时兼容 macOS 与 Windows，当前真机验收由 Codex 在 macOS 完成；Windows 只做 CI 构建、启动和核心自动化验证。
- 站点规模按 6–20 个设计，使用动态并发、随机刷新、错峰和退避。
- 首次启动必须测试登录成功后才能保存站点；支持常用账号模板和批量录入。
- 悬浮窗默认右上角，可切换左上角；左右切换站点，点击打开主面板。
- 默认 API Key 支持自动与手动模式；自动模式选择今天请求次数最多的 Key，手动模式永久保存并优先。
- 今日统计显示总 Token、输入、输出、缓存、实际消费和标准费用；金额按美元原值显示。
- 低余额通知阈值为 0.50 美元，通知总开关默认关闭。
- 动态标题按当前站余额切换两句用户确认文案，并有查询中兜底文案。
- 使用记录、渠道状态和主面板后续采用 `@product-design + Stitch / Stitch MCP` 高保真 UI 壳路线。
- 源代码发布到 Gitee：`https://gitee.com/zarq/Sub2API-Multi-Hub-Monitoring-Tool.git`。
- 用户确认需求总结无误，并选择 Codex 负责 macOS 真机测试及 Stitch Design QA。
- 用户曾确认文本视觉方案支持浅色、深色与跟随系统、默认浅色；该主题范围已被后续确认取代。液态玻璃适用边界不变。
- 用户确认密集表格、表单、渠道时间线和危险操作区使用高不透明表面，并要求支持减少透明效果与高对比度降级。
- 用户确认本项目不需要额外视觉图片。以上为设计确认，不代表 UI 壳、Stitch 产物或 Design QA 已完成。
- 2026-07-12 后续变更：取消深色模式、跟随系统模式和主题切换，产品只提供固定浅色模式；减少透明效果与高对比度作为浅色模式下的无障碍降级继续保留。此项为需求确认，不代表代码或 Stitch 产物已经同步完成。

## 2026-07-14 悬浮窗桌面层最终确认

- 应用版本继续保持 1.0 系列，工程和安装包采用 SemVer `1.0.0`。
- 本节为最新用户确认，覆盖此前可能把“桌面常驻”理解为置顶或切换应用时隐藏的表述。
