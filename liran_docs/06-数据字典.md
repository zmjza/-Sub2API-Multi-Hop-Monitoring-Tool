## 2026-07-18 外发版合并字段（1.1.0 已完成）

| 逻辑字段                       | 来源与语义                                          | 存储边界                             | 缺失处理                           |
| ------------------------------ | --------------------------------------------------- | ------------------------------------ | ---------------------------------- |
| `reasoningEffort`              | usage `reasoning_effort` 的安全枚举映射             | 按需内存/CSV，禁止写入敏感日志       | UI 显示 `—`                        |
| `cacheCreationTokens`          | usage `cache_creation_tokens` 或今日汇总对应字段    | 快照/按需查询沿用现有 Token 生命周期 | 不猜测，按既有零值/空值约定        |
| `durationMs`                   | usage `duration_ms`；今日统计为 `averageDurationMs` | 快照/按需查询，不创建完整历史库      | UI 显示 `—` 或既有空值             |
| `availableChannelRelationship` | `/channels/available` 的渠道、平台、分组、模型关系  | 运行时或短期能力缓存，不保存完整响应 | 关系不完整则 `unknown/unsupported` |
| `floatingOpacity`              | 用户设置，整数百分比 `35..100`，默认 `84`           | SQLite `AppSettings`，不写日志       | 非法值拒绝并回退默认               |

上述字段已在 1.1.0 完成实现、契约测试和 macOS/Windows 对应证据验证；Windows 证据仅代表交叉构建与结构检查，不代表 Windows 真机验收。

## 2026-07-18 1.2.0 优化字段

- `firstTokenMs`：usage `first_token_ms`，仅允许有限数值；负数在展示层视为无效并显示 `—`。
- `durationMs`：usage `duration_ms`，与首字使用相同的可读时长格式。
- `quota` / `quotaUsed`：`/keys` 安全摘要中的 Key 总额度/已用额度；仅手动 Key 且 quota 有效正数时参与总额减已用计算。
- `SiteSummary.note`：本地站点备注，最大 500 字，存储键为 `site:<siteId>:note`，不进入凭据和网络请求。

## 展示与持久化边界

- K/M 仅是 Renderer 展示格式，Token 原始整数继续用于计算、IPC 和 CSV，不把缩写字符串写回业务模型。
- `reasoningEffort` 保留上游可识别枚举；未知非空值以安全文本展示，不将其提升为已支持枚举。
- `effectiveRate` 必须同时记录 `source`，用于区分用户专属、Key 内嵌分组和可用分组默认倍率；没有可信来源时为 `null`。
- `floatingCorner` 默认 `right-top`。主窗口最小化与悬浮窗开关的组合属于窗口状态，不伪装成业务数据。
- 通知权限支持状态由操作系统实时查询，不把授权结果伪造成可写的应用偏好。

## 凭据生命周期

1. 表单中的明文密码只存在于最短必要内存。
2. 测试成功后使用 `safeStorage.encryptString` 加密，再保存密文或平台安全引用。
3. 站点凭据更新采用“新凭据先测试、成功后原子切换、最后清理旧引用”；失败时保留该站原凭据。
4. 常用账号模板已取消，不创建模板实体、模板关联或批量凭据同步生命周期。
5. 第一版已实现 `sites`、`credential_refs`、`auth_sessions`、`snapshots`、`settings` 和 `notification_states` 表；普通 SQLite 不保存密码、Token 或完整 Key。
6. 删除站点时清理站点凭据、Token、缓存和通知状态。

## 数据保留

- 普通缓存默认 30 天。
- 最新快照长期保留至站点删除，但超过 TTL 后标为过期且不计汇总。
- 使用记录列表仅按需缓存，不作为完整历史数据库。
- 日志保留策略在实现阶段确定，但必须经过脱敏且可由用户清理。

## 第一次 `/goal` 落地状态（2026-07-13）

- `settings` 已保存当前站点、自动/手动 Key 偏好、通知设置和窗口 bounds；开机启动由操作系统登录项保存。
- `notification_states` 已保存低余额 fingerprint 与最后发送时间，支持跨进程重启冷却。
- `sites.capability_json` 已保存核心能力、使用记录和渠道监控 supported/unsupported/error/unknown 状态。
- `snapshots` 已包含余额、今日请求数、输入/输出/缓存 Token、实际费用、标准费用、平均耗时和更新时间；30 天清理已接入启动与每日任务。
- 使用记录仍只按需读取，不进入完整长期数据库；CSV 由主进程即时生成并执行公式注入保护。
- 密码、access token、refresh token 只进入 `safeStorage` 加密载荷及最短必要内存；普通 SQLite、Renderer ViewModel 和 CSV 不包含这些字段。
